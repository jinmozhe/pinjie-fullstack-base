# pnpm 补丁缓存验证治理计划

## 1. 当前状态和结果

- 状态：已结束
- 结果：已完成；根规则、pnpm 运维指南和真实消费者解析检查已同步，全部允许门禁通过

## 2. 关联需求

无。此次更新收紧既有依赖安全验证与缓存排障边界，不新增产品能力。

## 3. 背景与目标

前次 query-string 安全补丁生成失败后，`node_modules/.pnpm` 保留多个历史实例。目标是将根锁文件、冻结安装和真实消费者解析作为补丁验证证据，避免目录缓存误导依赖判断。

## 4. 非目标

不升级依赖、不删除整个 `node_modules/.pnpm`、不修改 Umi 运行逻辑、不运行重型测试、不提交、推送、发布或部署。

## 5. 方案设计

- 根 `AGENTS.md` 规定 `.pnpm` 目录的派生属性、验证证据和受限清理边界。
- pnpm 运维指南说明带 `patchedDependencies` 的固定验证顺序。
- `check:dependencies` 从 Admin 实际 Umi 依赖链解析 `@umijs/history` 的 query-string，不枚举 `.pnpm` 缓存目录。

## 6. 全栈影响矩阵

| 范围 | 是否涉及 | 工作内容 | 前置依赖 | 验证 |
| --- | --- | --- | --- | --- |
| Backend | 不涉及 | Python 与 API 不变 | 无 | 核对无差异 |
| Admin | 涉及 | 从真实 Umi 依赖链验证补丁 | 已安装锁定依赖 | 依赖检查 |
| Web | 不涉及 | Web 依赖不变 | 无 | 核对无差异 |
| API Client | 不涉及 | 契约和客户端不变 | 无 | 核对无差异 |
| Database | 不涉及 | 无迁移或数据操作 | 无 | 不适用 |
| Deployment | 不涉及 | 无发布或部署变更 | 无 | 不适用 |
| Documentation | 涉及 | 根规则、pnpm 指南、计划和 Changelog | 实现结果 | 文档门禁 |

## 7. 风险与回滚

模块解析链反映真实消费者，优于 pnpm 内部目录格式。若 Umi 依赖关系变更，检查必须随真实所有者更新；回滚仅恢复本次规则、文档和检查脚本，不能将目录缓存当作修复依据。

## 8. 验证清单

- `pnpm install --frozen-lockfile`。
- `pnpm check:dependencies`。
- `pnpm check:workspace`、`pnpm check:boundaries`、`pnpm check:documents`、`pnpm check:text` 和 `pnpm lint:md`。
- 不执行 Vitest、production build、浏览器、pytest、本地 Security 扫描、发布或部署。
