# Admin 表格异常纵向滚动条修复计划

## 1. 当前状态和结果

- 当前状态：已结束
- 结果：已移除表格容器的重复滚动层，恢复 Ant Design 原生受控滚动行为。

## 2. 关联需求

- `BASE-ADMIN-005`：管理端必须适合高频工作操作，支持长文本和窄屏溢出处理。
- `BASE-QUAL-002`：已有功能、配置和 UI 行为必须在修改中得到保护。

## 3. 背景

Admin 公共样式对所有 `.ant-table-container` 强制设置 `overflow-x: auto`。该规则会使纵向 overflow 同时计算为 `auto`，导致普通列表也生成额外滚动容器并在右侧显示异常滚动条。管理员表和安全日志已经通过 Ant Design `scroll` 属性提供真实宽表的受控横向滚动，外层覆盖形成重复滚动层。

## 4. 目标

1. 移除普通 Admin 表格右侧的异常滚动条。
2. 保留表头和单元格单行展示规则。
3. 保留管理员表、安全日志等真实宽表已有的 Ant Design 受控横向滚动。
4. 保持用户、角色、资产等标准列表的弹性桌面布局。

## 5. 非目标

1. 不修改表格列、分页、筛选、批量操作和权限逻辑。
2. 不改变 Ant Design、ProComponents 或 Umi Max 依赖版本。
3. 不增加新的自定义滚动条样式。

## 6. 现状分析

- `.workspace-panel .ant-table-container` 当前设置 `overflow-x: auto`，覆盖 Ant Design 表格容器默认行为。
- `.workspace-panel .ant-table-cell` 的 `white-space: nowrap` 是项目明确要求，需要保留。
- `AdminsPage` 和三类安全日志表已通过 `scroll.x` 使用 Ant Design 内部滚动容器。
- 历史计划已明确要求标准桌面表格不出现无意义滚动，真实宽表和窄屏使用组件内部受控滚动。

## 7. 方案设计

1. 删除 `.workspace-panel .ant-table-container` 的全局 `overflow-x` 覆盖及冗余 `max-width` 包装。
2. 不给普通 ProTable 统一补充 `scroll.x`，避免重新制造桌面端无意义滚动。
3. 保留现有真实宽表页面自己的 `scroll.x` 配置。
4. 在 Admin 工程规范中明确禁止通过全局 `.ant-table-container` overflow 覆盖实现横向滚动。
