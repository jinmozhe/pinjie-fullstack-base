# GitHub CI 线上失败修复计划

## 当前状态和结果

- 当前状态：已结束
- 结果：已完成

## 关联需求

- 无。本计划修复已交付工程的线上质量门禁回归，不新增产品能力。

## 背景

首轮 GitHub Actions 中，Backend 迁移漂移检查和 Browser E2E 失败。Backend 失败来自 `request_logs` 表注释未被迁移记录；Browser E2E 首次失败集中在 Admin，Umi 代理改写了浏览器 `Origin`，触发 Backend 的严格来源校验，同时硬编码的 `localhost` 存在 Linux 回环地址解析差异。首轮修复复验后 Backend 已通过，Browser E2E 继续暴露登录响应体读取时序和 Admin 初始 HTML 可访问性元数据问题。

## 目标

- 使 Alembic `check` 能识别并复现 `request_logs` 的当前表注释。
- 使 Admin CI 代理使用工作流传入的 Backend 地址，并保留本地默认值。
- 确保 Playwright 在登录跳转前读取认证响应体，避免 Chromium 释放响应资源。
- 确保 Admin 初始 HTML 提供标题、语言和允许缩放的 viewport。
- 在本机完成受影响的最小充分验证，记录线上复验边界。

## 非目标

- 不改变认证、权限、数据库字段和业务行为。
- 不修改 GitHub 权限、发布或部署流程。

## 现状分析

- `apps/backend/app/db/models/identity.py` 定义了新的 `request_logs` 表注释，但 `20260820_01` 只增加 `request_body` 字段。
- `.github/workflows/ci-e2e.yml` 以 `127.0.0.1:8000` 启动 Backend；`scripts/e2e/run-e2e.mjs` 已向 Admin 进程传递 `BACKEND_INTERNAL_URL`，但 `apps/admin/config/config.ts` 未使用该变量且开启了 `changeOrigin`。
- Admin 登录用例等待响应后才读取 JSON；页面跳转后 Chromium 会释放旧响应体并使 `response.json()` 失败。
- Umi 默认 HTML 缺少标题和语言属性，默认 viewport 同时禁用用户缩放，触发 Axe 的三项 WCAG 违规。

## 方案设计

- 在 `20260820_01` 中增加 PostgreSQL 表注释变更，并在降级时恢复旧注释。
- Admin Umi proxy target 读取 `BACKEND_INTERNAL_URL`，无变量时默认 `http://127.0.0.1:8000`，并关闭 `changeOrigin` 保留浏览器来源。
- 保持 Admin 浏览器请求同源，通过 Umi 代理访问 Backend。
- Playwright 通过与页面共享 Cookie 的 APIRequest 执行管理员首次登录，在无导航竞争的条件下读取并检查响应 JSON，再打开受保护页面验证登录态。
- 通过 Umi 本地 HTML 插件统一设置 `lang="zh-CN"` 和允许缩放的 viewport，并由 Umi `title` 配置生成页面标题。
- E2E 启动器只接受 2xx 就绪响应，并等待 Admin `/umi.js` 完成首次编译后再启动 Playwright，避免根据 404 或 HTML 空壳判定服务就绪。

## 风险与回滚

- 表注释迁移只改变 PostgreSQL 元数据，不改变业务数据；回滚执行该迁移的 downgrade 即可。
- 代理默认地址从 `localhost` 改为 `127.0.0.1`，本地可通过 `BACKEND_INTERNAL_URL` 覆盖；保留 Origin 使 Backend 的 CSRF 来源校验继续生效。
- HTML 插件仅修改生成文档的根语言和 viewport，不改变 React 运行时；回滚时移除插件配置和文件即可。
- 管理员首次登录改用与页面共享 Cookie 的 APIRequest，不改变真实认证接口、Cookie 或后续页面断言；回滚时恢复表单提交登录。
