## 背景

提交 `4ba5378a7a80ba89ab9d260a25cfde193fcf4811` 的 GitHub Actions 中，Backend 迁移漂移检查和 Browser E2E 失败。Backend 失败来自 `request_logs` 表注释未被迁移记录；Browser E2E 失败集中在 Admin，Umi 代理改写了浏览器 `Origin`，触发 Backend 的严格来源校验，同时硬编码的 `localhost` 存在 Linux 回环地址解析差异。

## 目标

- 使 Alembic `check` 能识别并复现 `request_logs` 的当前表注释。
- 使 Admin CI 代理使用工作流传入的 Backend 地址，并保留本地默认值。
- 在本机完成受影响的最小充分验证，记录线上复验边界。

## 非目标

- 不改变认证、权限、数据库字段和业务行为。
- 不修改 GitHub 权限、发布或部署流程。

## 现状分析

- `apps/backend/app/db/models/identity.py` 定义了新的 `request_logs` 表注释，但 `20260820_01` 只增加 `request_body` 字段。
- `.github/workflows/ci-e2e.yml` 以 `127.0.0.1:8000` 启动 Backend；`scripts/e2e/run-e2e.mjs` 已向 Admin 进程传递 `BACKEND_INTERNAL_URL`，但 `apps/admin/config/config.ts` 未使用该变量且开启了 `changeOrigin`。

## 方案设计

- 在 `20260820_01` 中增加 PostgreSQL 表注释变更，并在降级时恢复旧注释。
- Admin Umi proxy target 读取 `BACKEND_INTERNAL_URL`，无变量时默认 `http://127.0.0.1:8000`，并关闭 `changeOrigin` 保留浏览器来源。
- 保持 Admin 浏览器请求同源，通过 Umi 代理访问 Backend。
