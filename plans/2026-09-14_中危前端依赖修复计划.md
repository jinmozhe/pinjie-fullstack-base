# 中危前端依赖修复计划

## 1. 当前状态和结果

- 状态：已结束
- 结果：已完成；安全版本、CommonJS 解码器补丁和全部允许的轻量门禁通过，重型验证未执行

## 2. 关联需求

关联 `BASE-SEC-005`、`BASE-OPS-002`、`BASE-OPS-003`、`BASE-OPS-008`；修复既有供应链风险，不新增产品能力。

## 3. 背景与目标

GitHub 10 条开放中危告警涉及 8 个公告、5 组依赖。Vitest 同一漏洞在多个包和清单中重复登记。现有 CI 阻断 High/Critical，中危需单独修复。目标是消费安全版本，保留 Umi Webpack、应用功能、测试范围与覆盖率阈值。

## 4. 非目标

不升级 Umi、React、Next.js 或无关依赖，不改变安全阈值、凭据、API、数据库和生产镜像。不运行未明确点名的 Vitest、build、浏览器、pytest 或本地安全扫描。

## 5. 现状与修复版本

| 依赖 | 当前版本 | 修复版本 | 影响 |
| --- | --- | --- | --- |
| decode-uri-component | 0.2.2 | 0.5.0 | Admin history → query-string 的畸形 URL 解码拒绝服务 |

## 6. 方案与规则落实

- 根 AGENTS、SECURITY、开发流程第 17 节：精确修改目标与必要子依赖，由 pnpm 生成唯一根锁文件；保留七天冷却、信任策略与安装脚本白名单。
- Admin AGENTS：保留 Umi 4.7.5 和两个既有补丁；对 query-string 6.14.1 明确适配安全解码器默认导出，单一版本，不增加猜测、双轨或运行时回退。
- Web AGENTS 与 [Vitest 4 迁移指南](https://github.com/vitest-dev/vitest/blob/v4.1.11/docs/guide/migration.md)：Vitest 与 coverage-v8 同步至 4.1.11，检查 Vite/Node、测试发现、Mock 和覆盖率配置；保留显式覆盖范围与 80% 门槛。
- 增加精确版本与导入迁移的轻量原生 Node 检查，接入既有依赖检查入口，不执行 Vitest 或本地漏洞扫描。
- plans 规则与 project-hygiene milestone 模式：同步本计划、两个索引、受影响测试策略和运维文档、Changelog。

1. 登记计划和两个索引。
2. 更新两端 package.json、pnpm-workspace.yaml 和精确导入补丁；由 pnpm 生成 pnpm-lock.yaml，核对差异与 frozen-lockfile 安装。

4. 同步文档与 Changelog，回写结果、结束计划，清理本次临时资源。

## 9. 风险与回滚

- Vitest 4 改变 Mock 与 V8 覆盖率映射，静态检查不能代替真实套件；不降低阈值或排除既有测试。
- query-string 安全解码器约束与默认导入补丁必须一起更新，不能单独删除一侧；Node 24 与现有 Webpack 为当前边界。
- override 与导入补丁由仓库维护者负责，2026-09-28 复核。上游 query-string/Umi 原生消费安全解码器后，迁移删除补丁、override 与精确版本守卫，继续保留安全版本和行为检查。
- 原 Git 基线可恢复；回滚仅恢复本次配置并由 pnpm 重建相应锁文件。旧版本会重新引入告警，不能将回退表述为安全修复或直接部署。
