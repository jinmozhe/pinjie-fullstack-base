# 全项目索引根目录迁移计划

## 当前状态和结果

- 状态：已结束
- 结果：已完成；唯一全项目索引已迁移到根目录 `PROJECT_INDEX.md`，84 个关联文档完成旧名称和路径替换，治理门禁与 Markdown 链接检查通过。

## 关联需求

- `BASE-DOC-001`：项目必须维护可直接定位项目身份、当前阶段、计划、系统状态和权威来源的全项目索引。
- `BASE-DOC-006`：当前文档和交付历史必须可导航并保持单一来源。

## 背景

迁移前，全项目索引位于 `.agents/` 受保护目录。Codex 对该目录内文件的日常写入需要申请宿主权限，反复增加实施摩擦。该文件只承担项目当前事实与任务导航，不属于 Antigravity 规则桥接文件，将它放在根目录能够保持与 `CHANGELOG.md`、`AGENTS.md` 等全局入口一致的可见性和可编辑性。

用户已明确要求不再保留 `.agents/` 内的旧索引文件，将其迁移并重命名为根目录 `PROJECT_INDEX.md`，同时全量更新项目内所有文档中的旧名称、路径、说明和关联。

## 目标

- 将原索引的完整内容迁移到根目录 `PROJECT_INDEX.md`。
- 删除旧路径文件，不保留跳转页、软链接或双份索引。
- 全量更新已跟踪文档中的旧文件名、路径、Markdown 链接和职责说明。
- 保持 `PROJECT_INDEX.md` 为全项目当前事实与任务导航的唯一权威来源。
- 保持 `.agents/rules/` 的 Antigravity 规则桥接职责不变。

## 非目标

- 不移动、删除或重命名任何既有计划文档。
- 不修改 Backend、Admin、Web、API Client、数据库或部署行为。
- 不调整 `.agents/rules/`、各级 `AGENTS.md` 的规则正文职责。
- 不修改 Codex 用户级配置、沙箱 ACL、Owner 或 DACL。
- 不执行 Git 提交、推送、Pull Request、发布或部署。

## 现状分析

- 原索引内容完整，可以原样迁移到根目录。
- 根 `AGENTS.md`、应用规则、README、PRD、ADR、架构文档、运维文档和历史计划均存在旧路径引用。
- 迁移前扫描发现 84 个文件包含旧索引名称、正斜杠路径或反斜杠路径。
- 旧路径属于 Codex 受保护路径，迁移删除需要对准确目标执行一次宿主权限操作；根目录新路径在标准工作区可直接维护。
- 历史计划永久保留文件路径和正文，仅更新已经失效的索引链接与名称，不改变原计划状态和实施事实。

## 方案设计

1. 使用 Git 感知的移动操作把 `.agents/` 内原索引迁移为根目录 `PROJECT_INDEX.md`，保留文件历史。
2. 对 Git 已跟踪文本文件执行严格、可校验的机械替换：
   - 旧的正斜杠路径替换为根目录文件名。
   - 旧的反斜杠路径替换为根目录文件名。
   - 剩余旧文件名替换为 `PROJECT_INDEX.md`。
3. 根据每个文档所在目录保持 Markdown 相对链接有效，例如 `docs/` 二级目录中的链接改为 `../../PROJECT_INDEX.md`。
4. 更新 ADR 0004、项目结构说明和 AI 协作流程中的位置说明，使根目录路径成为当前决策。
5. 在 `PROJECT_INDEX.md` 中更新自身入口、维护边界并登记本计划。
6. 在 `CHANGELOG.md` 中记录全项目索引迁移事实。
7. 通过全文零残留搜索、Markdown lint、文本卫生、工作区与模块边界检查验证迁移完整性。

## 风险与回滚

- 风险：遗漏旧路径会导致任务读取或文档链接失效。
- 控制：对全部 Git 已跟踪文本执行替换，并以 `rg` 零残留和 Markdown 链接路径检查验收。
- 风险：批量替换破坏 UTF-8、换行或历史计划正文。
- 控制：使用严格错误处理、UTF-8 无 BOM 写入、写前结果校验和写后文本卫生检查；只替换三个明确字符串。
- 风险：旧索引删除后外部书签失效。
- 控制：用户已明确要求不保留旧文件；仓库内引用全部同步，外部引用不在仓库控制范围内。
- 回滚：通过最近本地检查点恢复旧路径及引用，再删除未提交的根目录新索引。
