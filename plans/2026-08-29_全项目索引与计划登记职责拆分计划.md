# 全项目索引与计划登记职责拆分计划

## 当前状态和结果

- 状态：已结束
- 结果：已完成

## 关联需求

- `BASE-DOC-001`：项目必须维护能够快速定位身份、当前阶段、活动计划和权威来源的全项目索引。
- `BASE-DOC-004`：实现类工作必须通过全栈计划追踪。
- `BASE-DOC-005`：已存在计划及其永久登记必须保留。
- `BASE-DOC-006`：当前文档和交付历史必须可导航并保持单一来源。

## 背景

根目录 `PROJECT_INDEX.md` 当前同时承担项目当前事实入口、已结束计划摘要、全部计划永久登记、系统状态、权威来源和维护规则。计划数量增长后，当前入口被大量历史记录淹没，读取成本和维护范围持续扩大。

用户已确认采用职责拆分方案：根索引只保留项目身份、当前阶段、活动计划和权威入口；全部历史计划登记迁移到 `plans/INDEX.md`；`plans/README.md` 继续只保存计划规则和生命周期。

## 目标

- 将 `PROJECT_INDEX.md` 精简为高频当前事实入口。
- 新建 `plans/INDEX.md`，保存全部实施计划的永久登记、状态、结果、范围和用途。
- 保证每份 `plans/YYYY-MM-DD_*计划.md` 都在 `plans/INDEX.md` 唯一登记。
- 让 `PROJECT_INDEX.md` 只展示状态为待确认、待实施或实施中的活动计划；没有活动计划时明确显示“无”。
- 更新规则、README、ADR、架构和运维文档中的职责说明与维护路由。
- 保留全部既有计划原文、路径、状态和历史事实。

## 非目标

- 不删除、移动、重命名或改写任何既有实施计划文件。
- 不把 `CHANGELOG.md` 或 `PROJECT_INDEX.md` 移入 `docs/`。
- 不修改 Backend、Admin、Web、API Client、数据库或部署行为。
- 不改变 `plans/README.md` 的计划规则正文职责。
- 不执行 Git 提交、推送、Pull Request、发布或部署。

## 现状分析

- `PROJECT_INDEX.md` 当前包含 80 余条已结束计划摘要和完整登记表，历史内容占据主体。
- “当前开发计划”表实际包含大量已结束计划，不符合活动计划的名称和读取目标。
- “计划文档登记”表已经具备迁移到 `plans/INDEX.md` 所需的完整结构和数据。
- 根 `AGENTS.md`、`plans/README.md`、ADR 0004、README、项目结构和 AI 协作流程把永久登记职责指向 `PROJECT_INDEX.md`，需要同步更新。
- 历史计划中的 `PROJECT_INDEX.md` 引用主要记录当时的实施事实，不应机械改写；当前可执行规则和权威说明必须改为新职责。

## 方案设计

1. 新建 `plans/INDEX.md`，包含职责说明、维护规则和全部实施计划永久登记表。
2. 从 `PROJECT_INDEX.md` 迁移原“计划文档登记”数据，不复制为双份事实。
3. 将本计划加入 `plans/INDEX.md`，计划完成后保持“已结束 / 已完成”记录。
4. 重写 `PROJECT_INDEX.md`，只保留：
   - 项目身份与当前阶段。
   - 权威入口。
   - 活动计划。
   - 简短维护边界。
5. 根索引通过明确链接指向 `plans/INDEX.md`，不再保存历史计划登记或已结束计划摘要。
6. `plans/README.md` 继续定义计划创建、格式、状态、完成和保护规则，只增加到 `plans/INDEX.md` 的职责指针。
7. 更新根规则、README、PRD、ADR 0004、项目结构和 AI 协作流程，使当前事实与永久登记分别路由到两个入口。
8. `CHANGELOG.md` 记录索引职责拆分，不重复登记计划清单。

## 风险与回滚

- 风险：计划登记迁移遗漏，破坏永久追溯。
- 控制：机械提取原表，再以 `plans/*.md` 文件集合和登记路径集合做双向唯一性校验。
- 风险：根索引精简后遗漏关键当前事实入口。
- 控制：保留项目身份、当前阶段、权威入口、活动计划和维护边界，并通过 README 和根规则复读验证。
- 风险：`PROJECT_INDEX.md` 与 `plans/INDEX.md` 重复维护计划状态。
- 控制：根索引只保存活动计划，永久状态和结果只在 `plans/INDEX.md`；计划原文继续保存实施细节。
- 风险：历史计划中的旧职责表述形成误解。
- 控制：历史计划保留当时事实；当前规则、ADR、架构和运维文档统一指向新职责。
- 回滚：恢复最近本地检查点中的 `PROJECT_INDEX.md`，删除未提交的 `plans/INDEX.md`，并恢复本次权威文档修改。
