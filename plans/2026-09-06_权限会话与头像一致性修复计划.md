# 权限会话与头像一致性修复计划

## 当前状态和结果

- 状态：已结束
- 结果：已完成；四项修复、回归用例和文档同步已完成，适用轻量门禁通过，重型验证按项目策略未执行。

## 关联需求

- `BASE-BE-003`、`BASE-BE-005`、`BASE-ADMIN-004`、`BASE-WEB-002`、`BASE-SEC-002`、`BASE-SEC-006`。

## 背景

程序审查发现事务权限重查复用旧 ORM 状态、业务 401 误触发退出、刷新故障被原 401 掩盖，以及管理员头像写入与资产删除缺少共同锁。

## 目标

修复上述四项缺陷，保留现有接口、授权、审计及用户交互能力。

## 非目标

不调整数据库结构、依赖或生产配置，不提交、推送、发布或部署；不扩大为其他审查风险的修复。

## 现状分析

- 请求内共用 AsyncSession，普通加锁查询不会自动覆盖已加载的管理员属性。
- 两端请求管道依赖 HTTP 401 判断续期，刷新仅返回布尔值。
- Web SSR 恢复会话对所有失败跳转登录。
- 管理员资料保存接受头像 URL，资产删除只检查已提交的引用。

## 方案设计

- 管理员锁定读取显式刷新 ORM 状态，使事务内最终授权使用当前数据库值。
- 使用明确的会话错误码判断续期和会话失效，业务凭据错误原样返回。
- 刷新保留错误码、状态和重试元数据；临时故障不清理登录界面状态，SSR 恢复提供失败和重试。
- 站内上传头像地址归一化后查询并锁定对应资产，保存与资产删除使用相同资产行锁；外部 URL 保留。
