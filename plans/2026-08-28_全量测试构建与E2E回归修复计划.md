# 全量测试构建与 E2E 回归修复计划

## 1. 当前状态和结果

- 状态：已结束
- 结果：已完成

## 2. 关联需求

- `BASE-BE-002`、`BASE-BE-010`：保持管理端认证、错误语义与权限入口稳定。
- `BASE-API-001`：公开 OpenAPI 字段说明使用中文。
- `BASE-WEB-002`：保护用户头像上传、绑定和移除流程。
- `BASE-OPS-003`、`BASE-OPS-004`、`BASE-QUAL-002`：恢复已配置测试、构建和跨栈验证门禁。

## 3. 背景

用户明确授权执行本地全量 pytest、Admin 与 Web Vitest、生产构建和浏览器 E2E，并要求全部达标后提交和推送。首轮验证发现测试数据库迁移滞后、Backend 认证与 OpenAPI 回归、Backend 覆盖率不足、Web 头像测试夹具漂移，以及并行 Vitest 争用覆盖率目录。

## 4. 目标

1. 升级并验证隔离测试数据库，不触碰开发数据库。
2. 修复未认证管理请求的稳定认证语义和 OpenAPI 中文字段说明。
3. 补齐与新增系统概览和认证边界风险匹配的 Backend 测试覆盖。
4. 修正 Web 头像测试中的 UUID v7 契约和测试隔离问题。
5. 串行完成全量 pytest、两端 Vitest、两端生产构建和四项目浏览器 E2E。
6. 复读差异、清理本次测试产物后提交并推送当前分支。

## 5. 非目标

- 不新增产品能力。
- 不修改生产数据库、生产配置、发布、GHCR 或部署流程。
- 不替换现有前端组件体系或 UI 样式。

## 6. 现状分析

- `pinjie_fullstack_test` 已从 `20260825_03` 升级到 `20260827_03`，数据库结构回归已解除。
- Backend 全量 pytest 当前为 170 通过、2 失败，覆盖率 88.73%。
- Web Vitest 当前为 48 通过、2 失败，失败集中在旧 UUID 文本和头像移除测试状态。
- Admin 并行复核因两个 Vitest 进程争用同一覆盖率目录而失效，需要在无残留进程时串行重跑。

## 7. 方案设计

- 调整管理端当前身份依赖，使缺少认证 Cookie 时在数据库资源解析前返回稳定 401，同时保留已认证请求的真实数据库、Redis、会话和权限校验。
- 为系统概览嵌套字段补充 Pydantic `Field` 中文说明，并由 OpenAPI 测试机械校验。
- 通过用户可观察结果和失败分支补充 Backend 测试，不通过排除源码或降低阈值满足覆盖率。
- Web 测试夹具统一使用合法 UUID v7，并确保每项测试恢复 Mock 和 Query 状态。
- 测试和构建使用仓库已有脚本；E2E 使用真实 Backend、隔离 PostgreSQL 测试库、Redis、Admin 与 Web 生产产物。

## 11. 风险与回滚

- 认证依赖调整可能影响所有 Admin 受保护端点。通过无 Cookie、无效 Cookie、会话撤销、权限拒绝和完整 E2E 覆盖；回滚时恢复原依赖实现。
- E2E 会写入隔离测试数据库并启动本地服务。数据库名必须以 `_test` 结尾，结束后只回收本次启动的应用进程。
- 生成契约只能通过脚本更新，若出现非预期 Breaking Change 则停止提交并定位。
