# Admin 管理员资料编辑与安全操作整合计划

## 当前状态和结果

- 状态：已结束
- 结果：已完成

## 关联需求

- `BASE-BE-003`：管理员密码继续遵守统一长度与会话失效边界。
- `BASE-BE-005`：资料更新与凭据重置继续使用独立权限和受保护接口。
- `BASE-ADMIN-003`：补齐管理员管理的通用操作入口。
- `BASE-ADMIN-004`：覆盖权限、失败、成功和危险操作确认状态。
- `BASE-ADMIN-005`：保持紧凑、可扫描，并处理窄屏溢出。
- `BASE-ADMIN-006`：只通过共享 API Client 和统一 HTTP 管道消费后端契约。

## 背景

当前 `/admins` 已显示名称、账号、身份、角色、状态和更新时间，并提供“角色、停用/启用、会话”操作。列表接口已经返回 `avatar`，页面没有渲染头像，也没有资料编辑入口。

后端已经提供管理员密码重置接口、`admins:credentials:reset` 权限、二次确认、会话撤销和审计链，Admin 页面与 API 适配层尚未接入。当前管理员仍可在“个人设置”中修改自己的头像、显示名称和密码。

用户要求列表增加编辑功能，可修改头像和显示名称，并要求操作列采用 `width: "1%"` 与不换行约束。用户进一步确认需要从身份列切换超级管理员身份，并明确选择列只用于批量启用和停用。本项目管理员生命周期使用状态停用，不提供删除操作。

## 目标

1. 管理员主信息列显示头像、显示名称和登录账号，没有头像时显示文字回退头像。
2. 增加“编辑”入口，通过资料编辑抽屉修改头像和显示名称。
3. 将重置密码作为独立安全操作，通过专用表单和现有二次确认链执行。
4. 完整保留角色分配、启用/停用、会话查看与会话撤销能力。
5. 具有权限时可点击“身份”列打开超级管理员身份切换确认流程。
6. 操作列直接显示“编辑、角色、会话”，将“重置密码、启用/停用”放入“更多”菜单。
7. 操作列使用 `width: "1%"`，表头、单元格和操作容器统一禁止换行。
8. 增加选择列，并提供原子批量启用和批量停用操作。
9. 按权限和目标管理员状态显示、隐藏或禁用操作，服务端继续承担最终授权。
10. 桌面和移动视口下操作项不换行，页面本身不产生横向溢出。

## 非目标

1. 不修改管理员用户名。
2. 资料编辑抽屉不承载超级管理员身份切换，身份变更从“身份”列进入独立确认流程。
3. 不改变角色、会话、单项状态和密码重置的既有后端业务语义。
4. 不把密码字段合并进资料编辑表单。
5. 不增加管理员删除或批量删除操作。
6. 不修改普通用户列表、Web、上传存储驱动或部署配置。
7. 不把本计划的操作列样式批量扩展到其他 Admin 页面。

## 现状分析

1. `AdminRead`、数据库模型和列表 Presenter 已包含 `avatar`，列表可以直接消费该字段。
2. `AdminsPage` 只渲染 `display_name` 和 `username`，操作列使用固定 `220px` 并允许换行。
3. 当前操作列直接显示“角色、停用/启用、会话”；状态操作已禁止作用于当前管理员，角色操作尚未在客户端提前阻止修改自己。
4. `AdminUpdateIn` 当前只有 `display_name` 和 `is_superuser`，目标管理员头像更新需要扩展请求契约与 Service。
5. Admin 已有 `AvatarUploader`，可以上传头像并返回站内资源路径。
6. 后端密码重置接口成功后会提升凭据版本、撤销目标管理员会话并写入审计；Admin API 适配层尚无对应方法。
7. 后端会拒绝通过管理接口重置自己的密码，本人改密继续使用“个人设置”。
8. `AdminsPage` 当前未配置 `rowSelection`，页面和 Backend 均无管理员批量操作接口。
9. Backend 当前没有管理员删除端点，管理员生命周期由启用和停用状态管理。

## 方案设计

### 管理员信息列

1. 使用 Ant Design `Avatar` 显示 `row.avatar`。
2. 头像缺失时使用显示名称或用户名的首个可见字符回退；仍无法取得字符时使用管理员图标。
3. 头像、显示名称和用户名使用紧凑水平布局，名称区域保留现有主次层级和长文本收缩能力。

### 身份列切换

1. 保留“超级管理员”和“管理员”标签视觉；具有 `admins:update` 权限且目标不是自己时，把标签放入具有键盘语义的按钮中。
2. 点击身份只打开“设为超级管理员”或“取消超级管理员”确认流程，不直接提交变更。
3. 无权限或目标是当前管理员时保持静态标签，并通过 Tooltip 说明不可操作原因。
4. 确认后继续调用现有管理员更新接口，仅提交 `is_superuser`，并使用 `admins:superuser:change` 二次确认动作。
5. Backend 继续执行禁止修改自己、最后一名启用超级管理员保护、凭据版本提升、目标会话撤销和审计。

### 资料编辑抽屉

1. “编辑”作为第一个直接入口，仅在具有 `admins:update` 权限时显示。
2. 使用现有 Ant Design 表单体系，字段只包含头像和显示名称。
3. 头像复用 `AvatarUploader`，上传成功后回填资源路径，保存时和显示名称统一提交。
4. Backend 在 `AdminUpdateIn` 增加可选 `avatar`，沿用本人资料的长度、去空白和空值清除语义。
5. 成功后关闭抽屉并刷新管理员列表；失败时保留表单内容并展示可重试错误。
6. 当前管理员具有 `admins:update` 时允许从列表编辑自己的基础资料，“个人设置”继续保留。

### 重置密码

1. 重置密码放入“更多”，不进入资料编辑抽屉。
2. 仅在具有 `admins:credentials:reset` 权限且目标不是自己时显示。
3. 专用弹窗包含“新密码”和“确认新密码”，校验 6 至 64 个字符及两次输入一致。
4. 表单校验后进入现有 `ConfirmActionModal`，动作使用 `admins:credentials:reset`。
5. 成功后关闭弹窗、清空敏感表单并提示目标管理员历史会话已撤销；失败时明确反馈。

### 操作列安排

1. 直接入口按“编辑、角色、会话”排序。
2. “角色”继续受 `admins:roles:assign` 与 `roles:read` 控制；目标是当前管理员时禁用并提供说明。
3. “会话”继续受 `admins:sessions:read` 控制；抽屉中的“撤销全部”继续受 `admins:sessions:revoke` 控制并禁止作用于自己。
4. “更多”使用带 Tooltip 的省略号图标按钮，只在至少存在一个可用菜单项时显示。
5. “更多”先显示“重置密码”，分隔后显示“启用/停用”。状态操作继续受 `admins:update` 控制并禁止作用于自己。
6. 停用保留危险色、二次确认和成功反馈；移动入口不改变接口、权限和审计。

### 操作列宽度与响应式

1. 操作列设置 `width: "1%"`。
2. 表头和数据单元格设置 `whiteSpace: "nowrap"`，操作容器移除当前 `wrap`。
3. 移除 `220px` 固定宽度，由可见操作内容决定最小宽度。
4. 窄屏超宽时只允许表格内部横向滚动，不能造成 `document` 级横向溢出。
5. 权限导致操作数量变化时不保留固定空白。

### 选择列与批量状态操作

1. ProTable 增加 `rowSelection` 选择列，选择状态由页面本地管理；当前管理员行不可选，并显示原因。
2. 选中行后显示 ProTable 批量工具栏，提供“批量启用”和“批量停用”，不提供批量删除。
3. 批量状态变更继续使用 `admins:update` 权限和 `admins:status:change` 二次确认；一次确认只绑定一次明确的批量动作。
4. Backend 增加批量状态请求 Schema 与受保护端点，在单一事务中锁定全部目标管理员并执行全有或全无更新，禁止前端循环调用单项接口造成部分成功。
5. 批量停用继续保护当前管理员和最后一名启用的超级管理员；任一目标不允许操作时整批失败并返回明确原因。
6. 成功后清空选择并刷新列表；失败时保留选择，展示可重试错误，不返回假成功。

### 管理员状态生命周期

1. 当前管理员生命周期使用“停用”作为可恢复的离职和撤权手段，停用会提升凭据版本并撤销会话。
2. 管理员列表不显示单项删除或批量删除入口，选择列只服务于批量启用和批量停用。
3. 停用管理员继续保留历史会话、角色关系、资产上传者和审计操作者信息，满足项目的状态保留策略。

### 权限与安全边界

1. 客户端权限控制只改善体验，Backend 继续执行最终授权、状态检查、二次确认和审计。
2. 资料更新使用 `admins:update`，密码重置使用 `admins:credentials:reset`，两种操作不共享提交按钮或确认 Token。
3. 头像资产的上传者仍是当前操作管理员，目标管理员资料只保存公开资源路径。
4. 不在客户端状态、日志、错误消息或测试产物中持久化新密码和二次确认 Token。

## 风险与回滚

- 风险：不换行操作列在窄屏占用较宽。通过三个直接入口、“更多”收纳和表格内部滚动控制。
- 风险：上传头像后取消抽屉会保留未引用资产。沿用现有资产库行为，不自动删除用户已上传文件。
- 风险：不同权限组合可能遗漏入口。通过权限矩阵组件测试覆盖。
- 风险：批量状态变更可能产生部分成功或同时移除最后超级管理员。Backend 使用单事务、固定锁顺序和现有超级管理员保护，全有或全无提交。
- 风险：启用/停用移入菜单会改变操作习惯。保留明确文字、状态色、确认标题和成功反馈。
- 风险：公开 Schema 变化造成客户端漂移。严格按 Backend、OpenAPI、API Client、Admin 顺序实施。
- 回滚：精确恢复 Schema、Service、生成契约和 Admin 页面改动；无需数据库回滚，也不删除已上传资产。
