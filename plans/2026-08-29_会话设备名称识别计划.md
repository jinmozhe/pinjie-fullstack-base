- 实施边界：在既有 Session 数据结构和公开契约内，为 Web 与 Admin 新会话生成稳定的浏览器和操作系统展示名称，并提供旧会话显式回填工具。

## 关联需求

- `BASE-BE-003`：完善认证与会话基础能力中的登录设备识别。
- `BASE-ADMIN-003`：让用户与管理员会话管理展示可识别的客户端名称。
- `BASE-WEB-002`：让用户中心会话列表展示可识别的登录设备。

## 背景

Backend 已从登录请求读取、清理并截断 `User-Agent`，`user_sessions` 与 `admin_sessions` 也同时保存 `user_agent_summary` 和可空的 `device_name`。当前 Web 与 Admin 登录服务创建会话时固定写入 `device_name=None`，Admin 和 Web 会话列表遇到空值统一显示“未知设备”，因此正常浏览器登录也无法展示浏览器和操作系统。

## 目标

- 使用维护中的标准 User-Agent 解析库，避免项目自行维护浏览器正则规则。
- Web 与 Admin 创建会话时从已清理的 `user_agent_summary` 生成稳定展示名称。
- 展示名称只使用浏览器族和操作系统族，例如 `Chrome · Windows`，不承诺无法可靠获得的设备型号或 Windows 小版本。
- 保留原始、已清理的 User-Agent 摘要，用于审计和后续规则升级后的受控重算。
- 为既有空 `device_name` 会话提供默认 dry-run、显式 `--apply` 的回填工具。
- 解析结果只用于展示，不参与认证、授权、风控结论或可信设备判断。

## 非目标

- 不依赖支持范围有限的 User-Agent Client Hints，不请求高熵设备信息。
- 不精确识别 Windows 10 与 Windows 11、补丁版本、硬件型号或真实物理设备。
- 不把 User-Agent 或解析结果作为安全凭据，也不据此放宽任何认证和授权校验。
- 不修改 Session 表结构、API 字段、OpenAPI 或前端组件布局。
- 不在本次任务中自动执行回填工具的 `--apply`、真实数据库迁移、部署或远端操作。

## 现状分析

- `app/core/request_metadata.py` 已从请求头读取 `User-Agent`，移除控制字符并限制为 512 字符。
- `app/services/authentication.py` 创建 Web 与 Admin Session 时保存 `user_agent_summary`，但 `device_name` 固定为 `None`。
- Session Model、Alembic 结构和 `SessionRead` 已包含 `device_name`，无需数据库迁移和契约变化。
- Admin 的用户、管理员会话抽屉及 Web 用户中心都已消费 `device_name` 并提供“未知设备”回退。
- Backend 当前没有 User-Agent 解析依赖或统一解析入口。

## 方案设计

### 1. 解析边界

在 Backend 公共核心层增加纯函数解析模块，输入为已清理的可空 User-Agent，输出为不超过数据库字段长度的可空展示名称。解析规则由标准库提供浏览器族、操作系统族和设备族，项目只负责稳定清理与组合：

- 浏览器与操作系统均可识别：`浏览器 · 操作系统`。
- 只识别一项：直接返回该项。
- 空输入或两项都无法识别：返回 `None`，沿用既有“未知设备”契约。
- 过滤解析器的 `Other`、`Generic Smartphone` 等无信息占位值，不伪造精度。
- 不捕获未知解析异常；依赖或程序错误明确传播，避免静默隐藏实现故障。

### 2. 会话写入

Web 与 Admin 的 `_new_session` 统一调用解析函数，并在初次登录创建 Session 时保存 `device_name`。Refresh 只更新会话活动时间，不重命名既有设备，保证会话身份展示稳定。

### 3. 旧会话回填

增加独立脚本扫描 `device_name IS NULL` 且 `user_agent_summary IS NOT NULL` 的 Web 与 Admin 会话：

- 默认仅输出候选、可解析和无法解析数量，不写数据库。
- 只有显式 `--apply` 才在单一事务中写入可解析结果。
- 不覆盖已有 `device_name`，重复执行保持幂等。
- 不输出完整 User-Agent、主体标识或其他会话敏感信息。
- 本次只交付和静态验证脚本，不连接或修改真实数据库。

### 4. 依赖与隐私

引入官方 `ua-parser` Python 包并由 `uv.lock` 固定解析结果。解析规则升级属于依赖升级，继续经过依赖审查和验证。API 继续保留现有 `user_agent_summary` 字段，本次不扩大其前端用途；长期展示只消费标准化 `device_name`。

## 风险与回滚

- User-Agent 可以伪造，展示名称可能不准确；解析结果不参与任何安全判断。
- 浏览器规则会随依赖版本变化；锁文件固定版本，升级时复跑解析样例。
- 解析器出现程序异常会使登录明确失败，避免生成与实际不一致的安全元数据；可通过回滚依赖和解析接入恢复原行为。
- 回填工具只更新空值并默认 dry-run；执行 `--apply` 前必须核对目标环境和备份，回滚可按本次更新范围重新置空，但本计划不自动执行数据回滚。
- 源码回滚移除解析调用和依赖即可恢复“未知设备”行为，不影响 Session 表结构和公开契约。
