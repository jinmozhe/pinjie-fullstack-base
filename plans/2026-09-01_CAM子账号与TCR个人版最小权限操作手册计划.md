# CAM 子账号与 TCR 个人版最小权限操作手册计划

## 1. 当前状态和结果

- 状态：已结束
- 结果：已完成；独立 CAM 与 TCR 个人版操作手册、完整控制台与密码管理权限、三仓只读 JSON、账号创建、服务器登录、权限验收、轮换和排障步骤已交付

## 2. 关联需求

- `BASE-OPS-006`：生产部署必须具备可执行的安全升级、失败恢复和运维步骤。
- `BASE-OPS-009`：生产部署只使用经过验证的完整镜像 digest。
- `BASE-SEC-001`：密码、密钥和生产凭证不得进入仓库。
- `BASE-SEC-004`：生产变更必须具备目标核对、最小权限和回滚边界。
- `BASE-SEC-006`：认证、授权和高风险操作应具备可追溯边界。

## 3. 背景

项目已使用 CNB 构建、扫描并向腾讯云 TCR 个人版命名空间
`pinjie-fullstack-base` 发布 Backend、Web 和 Admin 三张镜像。现有发布身份
`tcr-publisher` 具备推送能力，生产服务器尚未建立独立的只读镜像拉取身份。

用户准备先通过 1Panel 人工部署一次，需要一份独立、可长期复用的操作手册，完整覆盖此前对话中出现的 CAM 子账号类型、用户信息、权限策略、标签、控制台访问、TCR 登录密码、用户级账号、服务级账号、多个命名空间和账号职责分离等问题。

## 4. 目标

1. 新增独立运维文档，说明为什么生产服务器使用 `tcr-puller`，禁止复用 `tcr-publisher`。
2. 基于腾讯云 TCR 个人版当前官方 CAM 资源模型，提供仅允许读取指定三个私有仓库的完整 JSON 策略。
3. 对照 `tcr-publisher` 的创建流程，逐页说明 CAM 自定义创建时用户类型、用户信息、访问方式、权限、空白模板和标签如何选择。
4. 区分 CAM 控制台登录密码、CAM API 密钥和 TCR Docker 登录固定密码，并说明各自是否需要创建、保存和轮换。
5. 说明个人版与企业版的用户级账号、服务级账号边界，避免把企业版功能误用于个人版。
6. 给出服务器和 1Panel 场景下的 TCR 登录、三仓拉取正向验证、推送和越权访问负向验证、凭证保存、轮换、禁用和故障排查步骤。
7. 说明一个 CAM 子账号可绑定多个命名空间或仓库策略，不要求按命名空间机械创建多个子账号；账号边界按用途、环境和风险决定。
8. 同步项目文档索引和相关生产运行手册入口，保持单一权威来源。

## 5. 非目标

- 不在本计划中登录腾讯云控制台或创建、禁用、删除真实 CAM 子账号。
- 不读取、保存或提交 `tcr-publisher`、`tcr-puller` 的真实密码、登录信息、`SecretId`、`SecretKey` 或 Docker 凭据文件。
- 不修改 CNB 密钥仓库、GitHub Secrets、TCR 仓库权限、生产服务器或 1Panel 配置。
- 不触发镜像发布、生产部署、数据库迁移、回滚、Tag 或 Release。
- 不把 TCR 企业版服务级账号流程写成个人版可用功能。

## 6. 现状分析

- 腾讯云官方个人版授权示例支持仓库级只读权限；当前已验证的发布策略进一步证明本项目使用带主账号 UIN 的个人版资源格式。
- 指定仓库的资源范围需要同时包含命名空间、仓库和仓库下级资源。三个仓库应逐一列出，禁止使用 `repo/*` 扩大到主账号全部个人版仓库。
- 个人版使用 `qcs::tcr::uin/<主账号UIN>:repo/<namespace>/<repository>` 资源格式；旧版 `ccr:*` 策略仍可能兼容，但新文档只使用当前 `tcr:*` API 3.0 格式。
- TCR 企业版的服务级账号支持按命名空间设置只读或读写权限，但腾讯云官方明确要求已购买企业版实例。当前项目使用个人版，因此生产拉取身份继续采用 CAM 子用户关联的个人版登录凭证。
- 个人版 TCR 登录密码是固定密码并且全地域一致。重置会影响同一账号在所有地域的 Registry 登录，需要在轮换前盘点使用位置。
- 当前运维文档已经说明生产服务器只保存独立只读 TCR 凭证，但缺少 CAM 控制台逐步配置、精确 JSON、验证和故障处理手册。

## 7. 方案设计

### 7.1 文档位置与职责

新增 `docs/operations/tencent-tcr-personal-cam-accounts.md`，作为项目内 CAM 与 TCR 个人版账号管理的唯一操作手册。其他运维文档只保留入口和与自身流程直接相关的简短约束。

### 7.2 正式手册结构

正式手册至少包含以下章节：

1. 适用范围、前提和安全边界。
2. `tcr-publisher`、`tcr-puller`、主账号和未来自动部署身份的职责矩阵。
3. 为什么区分发布与拉取账号，以及账号泄露后的影响范围。
4. 企业认证主账号使用 TCR 个人版和 CAM 子用户的边界。
5. 用户级账号、服务级账号、CAM 子用户和消息接收人的区别。
6. 多个命名空间是否需要多个 CAM 子账号的判断规则。
7. `tcr-puller` 的逐页创建步骤。
8. 使用 JSON 空白模板创建三仓只读策略的完整策略和字段解释。
9. 策略关联、标签设置、审阅和创建结果检查。
10. TCR 个人版初始化或重置 Docker 登录固定密码。
11. 服务器执行 `docker login`、按完整 digest 拉取和凭证存储。
12. 允许项和拒绝项的正反向验收清单。
13. 账号轮换、禁用、删除、主机下线和泄露响应。
14. 常见错误、原因、检查顺序和停止条件。
15. 官方文档链接、核对日期和时效性说明。

### 7.3 三仓只读策略边界

策略只允许读取以下仓库及其下级资源：

- `pinjie-fullstack-base/pinjie-fullstack-backend`
- `pinjie-fullstack-base/pinjie-fullstack-web`
- `pinjie-fullstack-base/pinjie-fullstack-admin`

允许动作限定为：

- `tcr:DescribeImagePersonal`
- `tcr:PullRepositoryPersonal`

策略不得包含：

- `tcr:*`
- `tcr:PushRepositoryPersonal`
- `tcr:Create*`
- `tcr:Delete*`
- `qcs::tcr::uin/<主账号UIN>:repo/*`
- CAM、CVM、COS、TKE 或其他腾讯云产品权限

### 7.4 账号创建选择

手册将明确以下默认选择：

- 创建方式：自定义创建。
- 用户类型：可访问资源并接收消息。
- 用途：机器拉取身份，不作为日常人员账号。
- 用户名：`tcr-puller`。
- 控制台访问：仅为个人版首次初始化和凭证管理保留所需能力；是否在初始化后禁用需要以实际 TCR 凭证失效行为验证，无法证明前不写成强制步骤。
- API 访问：默认不创建 `SecretId` 和 `SecretKey`，Docker Registry 登录不需要 CAM API 密钥。
- 权限：只关联项目专用三仓只读自定义策略，不附加预设全读写策略。
- 标签：没有现有组织级标签治理时留空；已有成本中心、环境或责任人标签时按主账号规范填写，标签不产生授权。

### 7.5 验证模型

正向验证：

- 子账号可初始化或管理自己的个人版 TCR 登录凭证。
- 生产服务器能登录 `ccr.ccs.tencentyun.com`。
- 三个指定仓库均可按完整 digest执行 `docker pull`。

负向验证：

- 对三个仓库执行 `docker push` 必须失败。
- 删除镜像、删除仓库和创建仓库必须失败。
- 拉取同主账号下未授权的其他命名空间或仓库必须失败。
- 不能访问与部署无关的腾讯云资源。

负向验证使用明确的无害测试目标，禁止覆盖现有标签、删除资源或向生产仓库写入测试内容。

## 11. 风险与回滚

- **个人版和企业版混用**：服务级账号只写为企业版能力，个人版流程使用 CAM 子用户和个人版登录固定密码。
- **资源路径过宽**：正式 JSON 逐一列出三个仓库及其下级资源，不授权全部仓库通配路径。
- **控制台操作级接口无法按仓库限制**：完整策略保留 Publisher 已验证的操作级控制台和密码管理动作，资源为 `*`；仓库级第二段只允许查看镜像和 Pull，明确记录全局元数据读取边界。
- **把 CAM 密钥当 Docker 密码**：手册分表解释三套凭证，并给出准确登录命令占位符。
- **个人版固定密码轮换扩大影响**：文档要求先盘点该账号在所有地域和服务器的使用位置，再重置并逐台更新。
- **负向验证产生真实写入**：只验证被拒绝，不创建、覆盖或删除真实仓库和标签。
- **腾讯云控制台变化**：文档保存官方链接和核对日期；按钮名称变化时以官方当前页面为准，权限动作和资源格式仍需重新核对。
- **文档回滚**：本任务只修改文档和索引，可通过对应 Git 差异恢复；不改变任何线上权限或凭证。
