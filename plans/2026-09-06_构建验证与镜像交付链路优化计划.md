- 结果：已完成；三个阶段本地实现与 PR 静态检查问题修复、脚本夹具、适用轻量门禁和文档同步已完成，真实云构建和生产验证未执行

## 背景

GitHub 承担源码质量和交接，CNB 在腾讯侧构建并发布到 TCR，1Panel 拉取固定 digest。现有浏览器流程没有实际使用 Admin 构建结果，验证串行，交接锁按提交拆分，生产组合仍依赖人工汇总。

## 目标

修正生产产物验证，缩短可并行检查的关键路径，减少重复扫描，提供候选镜像组合验收、同 digest 晋级、部署预检和非破坏性保留计划。

## 非目标

不执行云构建、真实镜像发布、仓库清理、生产迁移或部署；不改变业务能力，不增加 Kubernetes 或另一镜像仓库。本次不运行 production build、Vitest、pytest 和 Playwright 实例。Git 交付按后续显式 `$git-sync` 授权执行。

## 现状分析

- Full Validation 只手动运行，严格交接依赖其同 SHA 成功证据。
- CNB 三端独立构建、扫描并发布不可变标签，现有证据必须继续有效。
- TCR 个人版容量有限，保留策略应先产生可审查清单。

## 方案设计

- GitHub 拆分 Backend 与前端验证，前端构建产物供最终 E2E 使用，失败记录只保留白名单元数据和耗时。
- Admin E2E 使用实际生产 Nginx 配置和 dist；Web 使用 standalone，禁止静默复用未知服务。
- CNB main 交接使用统一锁，交接模式、理由与验证 Run 进入持久证据。
- Docker 依赖层只复制工作区清单、锁与安装钩子所需文件，源文件随后复制。
- Trivy 只扫描一次完整 JSON，转换过滤门禁报告和 SBOM。
- 手动镜像验收拉取三端固定 digest，核对交接来源和 OCI revision，在独立 PostgreSQL、Redis 和应用容器中运行现有 E2E。成功后输出部署组合与非敏感镜像变量，不重建镜像。该验证放在 GitHub 手动入口，生产拉取路径仍为 TCR 到腾讯云。
- 部署预检校验组合、镜像变量和 1Panel 导出的变量；保留工具仅计算候选，不删除注册表内容。

## 实施结果

1. Full Validation 已拆分为源码前置、并行 Backend 与 Admin/Web 验证，以及依赖全部成功的产物 E2E；Admin 使用生产 Nginx dist，Web 使用 standalone，证据升级 v2。失败保留阶段计时与脱敏浏览器结果，CI flaky 结果阻断。
2. CNB main 交接改为统一并发组，保存 SHA、验证模式、理由和 Run/attempt 的独立 Artifact。Docker 依赖层输入缩小为工作区清单、锁与安装钩子需要的文件。Trivy 保留一次完整扫描 JSON，通过离线转换与结构化漏洞检查完成门禁。
3. 新增手动 `Validate Candidate Images`，在隔离 Compose 环境核对并测试最终固定 digest，成功后生成同 digest 的部署组合和非敏感变量。工具支持来源证据、变更路径、OCI 标签、attestation、四个浏览器项目及测试资源清理检查。
4. 增加请求生成、可信 Run/Artifact 部署变量预检和只读 TCR 保留计划。模拟子进程覆盖来源失败、错误 digest、旧应用、浏览器失败、仅部分项目成功、清理失败、清单改写、失败 Run 和面板变量漂移；未调用真实 Docker、注册表或 GitHub 认证接口。
5. 适用仓库门禁通过；补充 actionlint 1.7.12 对三条工作流的静态检查和修改 JavaScript 入口语法检查通过。actionlint 为核对官方 SHA256 后下载的一次性辅助检查，未注册为项目正式门禁；未运行 ShellCheck 或 Pyflakes。
6. ADR、测试策略、发布、容器、1Panel 手册及文档索引已同步，新增候选镜像验收操作文档。
7. PR 检查暴露 Full Validation 内嵌表达式的 Bash 解析错误，已改用环境变量传参并增加 Semgrep 详细诊断。发布子进程限制为 Git、GitHub CLI、Docker 和当前 Node，禁止选项覆盖 Shell 禁用设置；负向夹具通过。Semgrep CE 1.173.0 对四个修复文件的严格扫描通过，工作区、边界、文本、Markdown 和文档门禁通过。Git 交付最终状态以 PR 和交付回复为准。
