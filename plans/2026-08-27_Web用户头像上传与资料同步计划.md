## 背景

统一文件资产服务已经支持用户和管理员双域上传。Web 用户可以通过 `POST /api/v1/assets/upload` 上传 `avatar` 场景的 JPEG、PNG 或 WebP 图片，单文件上限为 2 MB；Web 也已经提供可复用的 `AvatarUploader` 组件。

当前链路尚未闭合：`users` 表没有头像字段，`UserPrincipalOut` 和用户资料更新契约没有头像，`UserAccountService` 无法把已上传资产绑定为当前用户头像，`AccountCenter` 只显示用户名或显示名称的首字符。上传成功只能产生资产记录和文件，不能成为用户资料的一部分。

## 目标

1. 为普通用户增加可为空的头像资料字段，并通过 Alembic 安全迁移。
2. 用户只能把自己上传的 `avatar` 场景资产绑定为当前头像。
3. Web 用户中心支持上传、更换、移除和持久化头像。
4. Web 页头和个人资料区域优先显示真实头像，缺失或加载失败时回退为首字符。
5. 当前被用户或管理员头像引用的资产不能从资产管理中硬删除，避免产生已知断链。
6. 保留现有 Admin 头像、通用上传、个人资料、密码、会话和注销功能。

## 非目标

1. 不实现图片裁剪、旋转、滤镜、压缩、响应式多尺寸派生或 CDN 转换。
2. 不允许用户填写任意外部头像 URL，也不允许引用其他用户或管理员上传的资产。
3. 不为普通用户开放资产列表、资产批量管理或任意文件删除权限。
4. 不在换头像或移除头像时自动物理删除旧资产。
5. 不修改管理员头像编辑交互，不在 Admin 用户列表增加头像编辑入口。
6. 不增加头像审核、内容识别、隐私分级或具体业务画像。

## 现状分析

### 已有能力

- `UploadScene.AVATAR` 只允许 JPEG、PNG 和 WebP，场景上限 2 MB。
- Web 用户经过 Cookie、Origin、Session 和 CSRF 校验后可以上传 `avatar`、`attachment` 和 `temp` 场景。
- 资产记录包含 UUID、上传主体类型、上传主体 ID、场景、URL、文件键、MIME、大小和哈希。
- `AvatarUploader` 已处理文件类型、体积、上传状态、预览和错误反馈。
- Web 用户中心已经通过 `UserUpdateIn` 更新显示名称和邮箱，并通过 TanStack Query 保存用户资料状态。
- Admin 头像使用可为空的路径字段和首字符回退，可作为视觉回退参考。

### 缺口

- `User` 没有 `avatar` 字段和 Alembic 迁移。
- `UserPrincipalOut`、`AdminUserRead` 没有用户头像输出。
- 缺少把受控头像资产绑定到当前用户的专用 Schema、Service 和端点。
- `AvatarUploader` 只向调用方返回 URL，没有暴露完整 `AssetRead` 供所有权绑定使用。
- `AccountCenter` 没有头像上传、移除、保存状态和真实图片展示。
- 文件资产硬删除尚未检查用户或管理员头像引用，可能删除仍在使用的头像文件。

## 方案设计

### 数据模型与迁移

1. 在 `users` 表增加 `avatar VARCHAR(500) NULL`，中文注释为“用户头像站内资源路径”。
2. ORM `User.avatar` 使用 `str | None`，默认 `None`。
3. 新增 Alembic revision，只增加可空列，不回填历史数据，不锁定非空默认值。
4. `downgrade()` 只删除新列；执行降级会丢失头像绑定，必须在执行前明确确认。
5. 历史用户迁移后头像为空，Web 自动使用首字符回退。

### 头像绑定契约

1. 在 `UserPrincipalOut` 和 `AdminUserRead` 增加 `avatar: str | None`，描述为用户头像站内资源路径。
2. 新增 `UserAvatarUpdateIn`：
   - `asset_id: UUID | None`。
   - UUID 表示绑定已上传资产，`null` 表示移除当前头像。
3. 新增 `PUT /api/v1/users/me/avatar`，要求有效 Web 用户会话和 CSRF，返回更新后的 `UserPrincipalOut`。
4. `UserAccountService.update_avatar()` 在事务内锁定用户，并按 `asset_id` 校验：
   - 资产存在。
   - `uploader_type=user`。
   - `uploader_id` 等于当前用户 ID。
   - `scene=avatar`。
   - 资产 URL 是站内上传服务生成的受控路径。
5. 校验通过后把资产 URL 写入 `User.avatar`；`asset_id=null` 时设置为 `None`。
6. 不把头像 URL 加入通用 `UserUpdateIn`，避免显示名称和邮箱更新端点接受未经归属校验的任意路径。
7. 绑定头像不提升 `credential_version`，不撤销会话；后续 `/users/me`、登录、注册和 Refresh 返回的用户资料均包含最新头像。

### 资产引用保护

1. 新增只读头像引用查询，检查目标资产 URL 是否被 `users.avatar` 或 `admins.avatar` 使用。
2. 资产单条和批量硬删除在暂存文件前检查全部目标；任一资产仍被头像引用时整批返回 HTTP `409`，不移动文件、不删除元数据。
3. 引用检查覆盖启用、停用和软删除用户，保持回收站资料长期可恢复。
4. 用户更换或移除头像后，旧资产不再被资料引用，管理员可以通过现有文件资产页面删除。
5. 本计划不自动删除旧资产。头像绑定属于数据库事务，文件硬删除属于可补偿外部副作用，两者不合并为一个隐式跨系统事务。

### Web 上传与展示

1. 扩展现有 `ImageUploader` / `AvatarUploader`，保留 `onChange(url)`，新增可选 `onUploaded(asset)` 回调，避免破坏 Admin 等既有消费者。
2. 用户中心个人资料区增加头像区域：
   - 当前头像预览。
   - “选择图片”上传入口。
   - 已有头像时显示“移除头像”。
   - 支持 JPG、PNG、WebP，最多 2 MB。
3. 上传成功后使用返回的 `asset.id` 调用头像绑定端点；绑定成功后更新 `web-me` Query 数据并刷新 Server Component。
4. 上传成功但绑定失败时显示明确错误，不伪装为头像已保存；已上传但未绑定的资产保留在资产库供管理员后续清理。
5. 移除头像调用同一端点并传 `asset_id=null`，不自动删除原资产。
6. 页头头像优先显示 `user.avatar`；没有头像或图片加载失败时显示浅色首字符回退，首字符取显示名称或用户名第一个可见字符。
7. 保留个人资料表单对显示名称和邮箱的现有更新流程，头像保存状态与资料表单状态分别反馈，避免一次失败覆盖另一项成功结果。

### Admin 与注册创建链路

1. Admin 创建用户时不要求头像，新用户 `avatar=None`。
2. Admin 用户读取契约增加头像字段，但本计划不修改用户列表布局和操作入口。
3. 公开注册仍不接收头像；用户注册并登录后在用户中心上传。
4. 用户软删除和恢复保留头像路径，符合现有“资料长期保留并可恢复”的生命周期。

### 契约与文档

1. 按“Backend Model 与迁移、Schema 与 Router、根 OpenAPI、API Client、Web 适配”顺序同步。
2. `packages/api-client/src/` 只通过 `pnpm generate-api` 生成，不手工修改。
3. 更新 `docs/PROJECT_REQUIREMENTS.md` 中用户资料和 Web 用户中心验收边界。
4. 更新 `docs/architecture/file-asset-storage.md`，明确头像绑定、引用保护和旧资产保留策略。
5. 必要时更新认证架构对用户资料输出的说明；实施完成后同步 `CHANGELOG.md`、本计划和 `.agents/agents-index.md`。
6. 本方案沿用现有本地资产、用户资料和补偿删除架构，不新增存储驱动或不可逆技术取舍，暂不新增 ADR。

## 风险与回滚

### 风险

1. 只保存 URL 且不校验资产归属会允许跨用户引用，本计划必须在 Backend 通过 `asset_id` 做权威校验。
2. 上传成功、绑定失败会留下未引用资产；必须明确提示，不能自动删除结果未知的文件。
3. 用户和管理员头像使用路径字段而非数据库外键，资产硬删除必须显式执行引用查询，避免断链。
4. 历史或人工写入的失效头像路径仍可能加载失败，Web 必须提供首字符回退。
5. 新响应字段会影响所有 `UserPrincipalOut` 和 `AdminUserRead` 测试 Fixture，必须通过生成类型和类型检查完整适配。

### 回滚

1. 发布前可以整体撤销源码和迁移文件。
2. 已执行升级后，优先通过前向修复；确需降级时先确认头像数据可丢失，再删除可空列。
3. Web 交互异常时可以停止展示上传入口，Backend 头像数据和旧资料继续保留。
4. 资产引用保护异常时应停止硬删除并前向修复，禁止绕过检查强制删除文件。
