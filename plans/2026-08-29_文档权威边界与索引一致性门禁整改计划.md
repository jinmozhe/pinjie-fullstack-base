# 文档权威边界与索引一致性门禁整改计划

## 当前状态和结果

- 状态：已结束
- 结果：已完成

## 关联需求

- `BASE-GEN-004`：目标能力、当前状态、实施过程和交付历史分开维护。
- `BASE-DOC-001`：项目身份、当前阶段、活动计划和权威入口可稳定定位。
- `BASE-DOC-005`：全部实施计划及其永久登记保持完整一致。
- `BASE-DOC-006`：当前文档、治理入口和交付历史保持可导航且职责唯一。

## 背景

根目录 `PROJECT_INDEX.md` 已精简为项目身份、当前阶段、活动计划和权威入口，全部实施计划的永久登记已迁移到 `plans/INDEX.md`。全量只读审计确认已废弃的索引文件名和路径已经清零，计划文件、计划登记、专题文档索引和 Markdown 链接也保持完整。

审计同时发现，部分当前性规则和文档仍把 `PROJECT_INDEX.md` 描述为完整实现状态来源，部分流程只使用含义不明确的“索引”，`docs/` 的唯一来源声明没有区分专题文档与治理载体，三条已结束计划登记缺少合法结果前缀。现有 `check:governance` 不能机械发现这些问题，Backend 指令链距离 Codex 默认 32 KiB 上限也只剩少量空间。

## 目标

1. 明确项目阶段、详细实现、已交付变化和单次验证证据各自的权威来源。
2. 将当前性文档中的“索引”明确为根项目索引、计划永久登记或专题文档索引。
3. 将 `docs/` 的职责限定为专题项目文档的唯一存储和发布来源，明确治理入口和历史载体例外。
4. 修正 `plans/INDEX.md` 中不符合枚举规则的结果字段。
5. 新增可在 CI 中执行的文档治理一致性门禁和负向夹具。
6. 检查根规则与应用规则的组合体量，避免超过 Codex 默认项目指令上限。

## 非目标

- 不修改 Backend、Admin、Web、API Client、数据库或部署行为。
- 不删除、移动、重命名或重写任何历史计划。
- 不改写历史计划中能够说明当时状态的阶段性描述。
- 不提高用户个人 Codex 配置中的 `project_doc_max_bytes`。
- 不运行 production build、Vitest、pytest、Playwright、浏览器自动化或数据库验证。

## 现状分析

1. 受版本控制的 140 个 Markdown 文件中没有已废弃的索引文件名和路径。
2. `plans/` 中 80 份实施计划与 `plans/INDEX.md` 的 80 条登记双向一致，但三条已结束记录没有以 `已完成`、`已取消` 或 `已替代` 开头。
3. `PROJECT_INDEX.md` 只有 34 行，却仍被根规则、PRD 和项目结构文档描述为完整实现状态来源。
4. `docs/operations/ai-assisted-development-workflow.md` 在多个步骤只写“索引”或“同步索引”，无法唯一确定目标文件。
5. `docs/` 之外合法存在 `AGENTS.md`、`PROJECT_INDEX.md`、`plans/`、`README.md`、`SECURITY.md` 和 `CHANGELOG.md`，绝对化的“项目文档唯一来源”定义会造成职责冲突。
6. 根规则与 Backend 规则组合为 30,426 bytes，低于默认 32 KiB，但需要自动门禁防止继续增长后发生截断。

## 方案设计

### 权威来源分层

- `PROJECT_INDEX.md`：项目身份、当前阶段、活动计划和权威入口。
- 实际源码、配置、迁移、生成契约和专题架构文档：详细实现状态。
- `CHANGELOG.md`：已交付能力和版本变化。
- `plans/*.md`：单次任务范围、实施、验证和剩余问题。
- `plans/INDEX.md`：全部实施计划的路径、状态、结果、范围和用途。

### 文档载体边界

`docs/` 定义为专题项目文档的唯一存储和发布来源，用于 PRD、ADR、架构、蓝图和运维手册。根规则、根项目索引、计划、README、安全策略和 Changelog 按各自职责继续保存在现有稳定路径，不被描述为 `docs/` 副本。

### 自动门禁

新增文档治理检查脚本并接入 `check:governance`，至少验证：

1. 受版本控制和未忽略文本中不存在已废弃的索引名称或路径。
2. `plans/` 实施计划与 `plans/INDEX.md` 登记集合完全一致且无重复。
3. 计划登记状态和结果使用合法枚举。
4. 活动计划集合与 `PROJECT_INDEX.md` 完全一致。
5. `docs/README.md` 完整登记 `docs/` 下除自身外的 Markdown 文档。
6. 根与应用级 `AGENTS.md` 组合不超过默认 32 KiB，并保留至少 1 KiB 安全余量。
7. 四个 Antigravity 规则桥接目标存在且引用准确，仓库中不存在 `AGENTS.override.md` 或第二份规则正文。

负向夹具分别制造废弃名称、漏登记、重复登记、非法状态、非法结果、活动计划漂移、专题文档漏登记、桥接缺失和指令超限，确认门禁全部拒绝。

## 风险与回滚

- 风险：门禁解析 Markdown 表格时与文档格式耦合。控制：固定登记格式并通过正向、负向夹具验证。
- 风险：误把历史计划中的阶段性事实当成当前规则修改。控制：门禁只禁止旧文件名，不改写其他历史叙事。
- 风险：指令体量门禁过度限制正常增长。控制：采用 Codex 官方默认上限，只对根规则与每个应用规则的实际加载组合检查。
- 回滚：按 Git 差异逐文件恢复本计划涉及的文档和脚本，不删除任何已有计划资产。
