# GitHub Wiki 停用与文档单一来源计划

## 1. 当前状态

- 状态：已结束
- 结果：已完成
- 创建日期：2026-08-12
- 影响范围：全仓库文档治理、GitHub Wiki、项目规则和索引

## 1.1 关联需求

`BASE-DOC-006`。

## 2. 背景

本仓库已经使用 `docs/` 和 `docs/README.md` 维护完整项目文档。此前根据用户要求初始化 GitHub Wiki，并将 `docs/` 同步到 Wiki；实际验证发现 GitHub Wiki 会扁平化页面展示和解释相对链接，导致目录语义与文档关联路径失真，同时形成第二份文档副本。

用户现已明确要求清空并关闭 GitHub Wiki，后续只使用仓库内 `docs/`。

## 3. 目标

1. 清空 GitHub Wiki 当前全部页面和同步清单。
2. 在 GitHub 仓库设置中关闭 Wiki 功能。
3. 明确 `docs/` 是本仓库项目文档的唯一来源和唯一发布载体。
4. 约束后续 Git 同步流程跳过 Wiki 检查和同步，即使历史 Wiki Git 远程仍可探测。
5. 保留原 Wiki 初始化计划及历史提交，记录后续停用决策，确保过程可追溯。

## 4. 非目标

1. 不删除或改写主仓库 `docs/` 文档。
2. 不删除、移动或重命名任何现有计划文档。
3. 不改写主仓库或 Wiki 的既有 Git 历史。
4. 不修改个人全局 `git-sync` 技能。

## 5. 现状分析

1. 主仓库 `docs/` 已有完整索引和稳定目录结构。
2. Wiki `master` 当前提交为 `5ac80bfc978e9a590d46266d6f44ce7c4d2c0252`，包含独立首页、12 份同步文档和 `.docs-sync-manifest`。
3. GitHub Wiki 页面展示会丢失部分目录上下文，仓库相对链接不适合作为 Wiki 页面链接直接复用。
4. `git-sync` 只要求同步已经存在的 Wiki；Wiki 未初始化时应跳过。此前初始化动作来自用户明确要求，不是技能自动要求。

## 6. 方案设计

1. 克隆 Wiki 到系统临时目录，核对远程、分支和文件清单。
2. 删除 Wiki 当前全部已跟踪页面和 `.docs-sync-manifest`，使用普通删除提交推送，不改写历史。
3. 在 GitHub 仓库设置中关闭 Wiki 功能，并核对仓库导航不再显示 Wiki。
4. 更新根 `AGENTS.md`、`docs/README.md`、ADR、产品需求、全项目索引和 Changelog，记录 `docs/` 单一来源约束。
5. 更新原 Wiki 初始化计划，追加后续停用事实，不删除原实施记录。
6. 完成验证后提交并推送主仓库治理变更；项目级规则生效后，后续 `git-sync` 跳过 Wiki。

## 10. 风险与回滚

1. 风险：误删主仓库文档。控制方式是所有删除只在系统临时目录中的 Wiki 克隆执行，主仓库 `docs/` 只修改索引说明。
2. 风险：关闭 Wiki 后无法从页面访问历史内容。Wiki 删除提交和既有提交仍保留在 Git 历史中，需要时可重新启用并通过后续提交恢复。
3. 风险：后续同步技能再次写入 Wiki。控制方式是把禁止 Wiki 的项目级规则写入根 `AGENTS.md`，项目规则优先于通用技能的可选 Wiki 流程。
4. 回滚：在 GitHub 设置中重新启用 Wiki，并在 Wiki 仓库通过普通恢复提交恢复指定历史树；不改写历史。
