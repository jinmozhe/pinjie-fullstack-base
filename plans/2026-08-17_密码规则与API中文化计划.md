## 背景

当前用户和管理员的新密码主要采用 12 至 128 个字符的约束，登录、旧密码校验和部分前端输入使用不同边界。FastAPI 自动文档、接口摘要、模型说明和统一响应的顶层 `message` 仍包含大量英文，不能满足当前项目面向中文使用者的本地开发与接口联调要求。

## 目标

1. 用户和管理员的密码设置规则统一为 6 至 64 个字符。
2. 注册、修改密码、重置密码、创建用户、创建管理员、初始管理员脚本及两个前端的输入提示采用相同规则。
3. 登录和当前密码校验输入统一限制最大 64 个字符，避免各入口继续接受超出新规则的密码。
4. 将 `/docs` 中面向开发者显示的标题、说明、接口分组、接口摘要、Schema 字段说明、响应说明和示例描述改为中文。
5. 保留 API 路径、HTTP 方法、参数名、字段名、Schema 名、错误 `code`、`operationId`、媒体类型和其他程序化标识的英文形式。
6. 将全部业务成功、业务失败、校验失败、HTTP 异常、限流异常和内部错误响应的顶层 `message` 改为对应中文。
7. 重新导出根 `openapi.json`、生成共享 API Client，并完成 Backend、Admin、Web 联合验证。

## 非目标

- 不修改 API 路径、HTTP 方法、请求字段名、响应字段名或错误 `code`。
- 不修改认证架构、Cookie、JWT、RBAC、数据库模型、迁移或已有账号密码哈希。
- 不把 Pydantic 校验错误 `details` 中的机器类型、字段路径和底层错误标识强制翻译为中文；顶层 `message` 必须为中文。
- 不启动或保留 Backend、Admin、Web 开发服务。
- 不提交、不推送、不发布镜像、不部署生产环境。

## 现状分析

1. Backend 的用户、管理员和认证 Schema 中，新密码约束主要为 12 至 128 个字符；登录密码和当前密码边界主要为 1 至 128 个字符。
2. 初始管理员脚本独立校验 12 至 128 个字符，需要与 API 规则同步。
3. Admin 和 Web 的表单校验、输入属性、帮助文本及测试中存在相同旧边界。
4. Backend Router、统一响应、异常处理、依赖、限流和 Service 中存在英文成功或错误 `message`。
5. 当前约 39 条 OpenAPI 路径的接口摘要、标签和自动响应说明包含英文；部分 Pydantic 模型说明也会直接进入 `/docs`。
6. 根 `openapi.json` 和 `packages/api-client/src/` 均为生成资产，禁止手工修改。

## 方案设计

1. 在 Backend 请求 Schema 和初始管理员脚本中统一密码长度常量或等价约束，所有创建或设置新密码的入口使用 6 至 64 个字符。
2. 登录密码、当前密码和管理员二次确认密码保留“凭据校验”语义，最小长度不用于判断账号是否存在，但最大长度统一为 64；前端输入同时使用 `minLength`、`maxLength` 和中文校验提示。
3. 逐项修改 Backend 的统一响应、异常处理、Router、依赖、限流与 Service 消息，保持错误 `code` 和 HTTP 状态不变。
4. 对 Starlette/FastAPI 自动异常建立明确的中文顶层消息映射，禁止把框架英文 `detail` 直接作为顶层 `message`；允许结构化 `details` 保留调试所需的机器信息。
5. 将 FastAPI 应用元数据、Router 标签、端点摘要和描述、Schema 字段描述改为中文。
6. 通过结构化 OpenAPI 生成逻辑统一替换框架自动产生的 `Successful Response`、`Validation Error` 等展示文本，保持契约结构和标识稳定。
7. 补充自动化测试，扫描导出的 OpenAPI 描述和运行时顶层 `message`，防止英文描述或消息重新进入公开接口。
8. 按 Backend 实现、导出根 `openapi.json`、运行 `pnpm generate-api`、适配 Admin/Web 的顺序同步契约和消费者。

## 风险与回滚

1. 风险：密码最小长度从 12 降至 6 会降低对弱口令的基础防护。账号锁定、限流和 Argon2id 哈希仍保留，但无法抵消用户选择简单密码的全部风险。
2. 风险：统一最大长度为 64 后，现存密码超过 64 个字符的账号将无法通过登录或旧密码输入校验，需要通过管理员重置或受控数据处理改为符合新规则的密码。
3. 风险：OpenAPI 展示文本变化会造成根契约和生成 Client 的注释差异，但不得改变路径、字段或运行时类型。
4. 风险：部分第三方框架错误细节由 Pydantic 生成；本计划保证顶层 `message` 和 `/docs` 描述中文化，不伪造或破坏机器可读的底层错误结构。
5. 回滚：密码边界和前端校验可按同一提交整体恢复到 12 至 128；已经设置为 6 至 11 个字符的密码在回滚后需要重置。
6. 回滚：响应文本与 OpenAPI 展示文本可恢复旧文案，错误 `code` 和契约字段始终保持稳定。
