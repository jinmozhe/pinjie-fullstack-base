## 3. 背景

项目已经具有根和三个应用级 `AGENTS.md`、Antigravity 桥接规则、全项目索引、PRD、计划规范、ADR、架构文档、运维手册、安全策略、OpenAPI 契约和 Changelog，但目前缺少一份面向项目维护者的完整说明，解释 AI 助手在不同任务中如何发现、选择、读取和应用这些资料。

用户需要明确以下问题：

1. 哪些规则由工具自动发现，哪些文档必须由项目规则主动读取。
2. `SECURITY.md`、应用级 `AGENTS.md`、PRD 和 Backend 工程标准何时会用到。
3. Backend、Admin、Web、跨栈、数据库、部署、安全、评审、故障和文档治理等常见任务的读取顺序。
4. AI 如何从任务描述和目标文件路径判断需要追加读取哪些专题文档。
5. 从任务进入、现状确认、计划、用户确认、实施、契约同步、验证到交付的完整链路。
6. Codex 与 Antigravity 的规则加载方式有什么区别，以及如何验证规则确实生效。

## 4. 目标

1. 新增一份可以独立阅读的 AI 助手开发与文档读取指南。
2. 区分平台自动加载、项目规则强制主动读取、按任务触发读取和无需默认读取四种机制。
3. 为全仓库常见任务提供明确的文档读取矩阵和流程图。
4. 解释每类文档的权威职责、使用场景、是否自动加载和如何得知需要读取。
5. 说明计划门禁、用户授权、敏感信息、高风险操作和生产变更边界。
6. 说明跨 Backend、OpenAPI、API Client、Admin、Web 和数据库的开发及验证顺序。
7. 让维护者能够检查 AI 是否漏读、读错或把目标文档误当成当前事实。

## 5. 非目标

1. 不复制根或应用级 `AGENTS.md` 的完整规则正文。
2. 不复制 PRD、架构文档、运维手册、ADR 和计划中的完整事实。
3. 不修改 Codex、Antigravity 或其他 AI 工具的个人全局配置。
4. 不新增新的规则发现机制、桥接规则、Skill、Hook 或 CI 门禁。
5. 不修改 Backend、Admin、Web、API Client、数据库和部署实现。
6. 不声称所有 AI 工具都原生支持 `AGENTS.md`；只描述本项目已确认的 Codex 和 Antigravity 链路，并为其他工具给出最低接入要求。
7. 不提交、推送、发布或部署本次文档修改。

## 6. 现状分析

### 6.1 Codex 自动发现事实

OpenAI 官方文档确认：Codex 在一次运行开始时建立指令链；先读取个人 Codex Home 中的全局规则，再从项目根目录向当前工作目录逐级查找 `AGENTS.override.md`、`AGENTS.md` 和已配置的候选文件，每级目录最多取一份，越接近当前目录的规则优先级越高。

本项目通常从 Monorepo 根目录启动 Codex，因此根 `AGENTS.md` 会由平台自动发现。嵌套的 `apps/backend/AGENTS.md`、`apps/admin/AGENTS.md` 和 `apps/web/AGENTS.md` 是否进入平台初始指令链取决于任务的当前工作目录，不能只依赖自动发现。根规则已经要求 AI 先读取 `PROJECT_INDEX.md`，再根据任务路径主动读取相应应用级规则。

### 6.2 Antigravity 自动路由事实

ADR 0002 已确认 Antigravity 通过 `.agents/rules/` 加载项目规则：

- `00-repository.md` 为 Always On，并引用根 `AGENTS.md`。
- `10-backend.md`、`20-admin.md` 和 `30-web.md` 按目标路径 Glob 激活并引用对应应用级 `AGENTS.md`。
- `.agents/rules/` 只负责路由，规则正文仍由 `AGENTS.md` 唯一维护。

### 6.3 普通项目文档不会自动加载

`SECURITY.md`、`docs/PROJECT_REQUIREMENTS.md`、`docs/architecture/*.md`、`docs/operations/*.md`、`docs/adr/*.md`、`plans/*.md`、`CHANGELOG.md` 和生成契约不会因文件存在自动进入 AI 上下文。AI 通过根规则、应用规则、全项目索引、计划和任务关键词得知需要读取哪些文档，并使用文件工具主动打开。

### 7.3 文档读取分类

| 分类 | 定义 | 本项目示例 |
| --- | --- | --- |
| 平台自动加载 | AI 工具按自身规则发现机制直接加入指令上下文 | Codex 根 `AGENTS.md`；Antigravity Always On 和匹配 Glob 的桥接规则 |
| 项目强制主动读取 | 自动加载的根规则明确要求 AI 使用文件工具打开 | `PROJECT_INDEX.md`、匹配任务范围的应用级 `AGENTS.md`、活动计划 |
| 按任务触发读取 | 根据路径、变更类型、风险和关键词选择相应权威文档 | PRD、专题架构、运维手册、安全策略、ADR、蓝图、契约和 Changelog |
| 默认无需读取 | 当前任务与该文档职责没有关系时不打开 | 无关领域蓝图、无关应用规则、已结束且不相关的历史计划 |

### 7.4 全任务共同链路

指南将明确以下固定顺序：

```text
接收用户任务
-> 确认工作区、目标路径和操作类型
-> 加载根规则并读取全项目索引
-> 加载受影响应用级规则
-> 读取当前事实和活动计划
-> 按主题读取 PRD、架构、安全、运维、ADR 或蓝图
-> 判断是否必须新建或续接计划
-> 取得用户确认和相应操作授权
-> 读取目标实现并进行影响分析
-> 实施最小范围变更
-> 同步契约、迁移、测试和文档
-> 运行最小充分验证
-> 回写计划、索引和 Changelog
-> 报告已通过、失败、跳过、未执行和剩余风险
```

### 7.6 重点文件解释

指南将明确：

- 根 `AGENTS.md`：Codex 通常自动加载；全仓库长期规则和读取总入口。
- `PROJECT_INDEX.md`：不会自动加载；每个任务按根规则主动读取，用于确认当前事实、活动计划和权威来源。
- `apps/*/AGENTS.md`：Codex 是否平台自动加载受当前工作目录影响；本项目要求按任务范围主动保证加载。Antigravity 按 Glob 桥接加载。
- `SECURITY.md`：不会自动加载；涉及安全、敏感数据、认证权限、漏洞、依赖供应链、公开披露和高风险生产变更时读取。
- `docs/PROJECT_REQUIREMENTS.md`：不会自动加载；新增、修改、取消产品能力和创建实现计划时读取，用于判断目标与非目标，不能用于判断当前完成度。
- `docs/architecture/backend-engineering-standard.md`：不会自动加载；Backend 详细设计、实施、代码评审和验证时，由 Backend `AGENTS.md` 强制读取。
- 五份专题架构文档：不会自动加载；按 Backend 规则和任务主题读取。
- `plans/README.md` 和活动计划：实现或治理变更时读取；已有匹配活动计划必须续接，不能另起无关计划。
- `docs/operations/`：执行启动、部署、备份、恢复和事故操作前读取。
- ADR：需要理解或改变重大技术取舍时读取；普通实现无需遍历全部 ADR。
- `CHANGELOG.md`：实施结束和交付事实同步时读取，不作为规则或当前状态来源。

### 7.7 反误导规则

1. 明确“自动加载”只表示进入 AI 指令上下文，不表示 AI 已读取所有被链接文档。
2. 明确普通 Markdown 链接不会自动展开，AI 必须主动调用文件读取工具。
3. 明确 PRD 描述目标能力，索引描述当前事实，不能相互替代。
4. 明确已结束计划仍永久保留，但普通任务不需要读取所有历史计划。
5. 明确生成契约和源码应按影响范围读取，禁止为了“完整”无差别加载整个仓库。
6. 明确用户要求实现不自动授权提交、推送、发布、部署、迁移生产数据或其他独立高风险动作。
7. 明确不同 AI 工具的自动发现能力可能变化，无法证明自动加载时必须显式读取并报告。

## 11. 风险与回滚

| 风险 | 控制方式 | 回滚方式 |
| --- | --- | --- |
| 把普通文档误写成自动加载 | 明确区分四种加载机制，并引用官方和项目事实 | 修正分类和读取说明 |
| 复制现有规则形成第二来源 | 指南只写路由、职责和场景，具体规则使用链接 | 删除重复正文，保留权威链接 |
| 文档过长难以使用 | 同时提供完整说明、场景矩阵和快速检查清单 | 精简重复段落，不删除必要场景 |
| Codex 与 Antigravity 行为混淆 | 分别说明发现机制和本项目桥接方案 | 按 ADR 0002 和官方文档修正 |
| 未来工具行为变化 | 标明核验日期和重新核验入口 | 更新当前指南，不复制旧版本 |
| 覆盖用户已有修改 | 只编辑本计划列出的文档范围 | 逐项撤回本任务新增内容 |

本计划只修改文本资产，可逐项撤回本任务新增内容。计划文件及索引登记按项目规则永久保留，不能通过删除计划回滚。
