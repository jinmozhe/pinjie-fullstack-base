## 背景

角色权限弹窗已经能够把后端扁平权限目录转换为 TreeSelect 分组，但仍需点击下拉后才能查看和操作权限。用户确认将其更新为 Ant Design `Tree`，在点击角色列表“权限”后直接展示完整权限树，并补充全选、反选等批量操作。

Ant Design Tree 支持 `checkable`、受控 `checkedKeys`、父子关联、禁用节点、展开控制和虚拟滚动。全选、反选、清空属于业务工具栏能力，需要根据真实权限叶节点自行计算。

## 目标

- 权限弹窗打开后直接展示完整权限树，不再使用下拉选择器。
- 保留已有权限分组、未知权限兜底、停用状态和真实权限码提交过滤。
- 支持权限名称与代码搜索，并保留匹配节点的父级分组。
- 增加全选、反选、清空、展开全部和收起全部。
- 显示已选启用权限数和启用权限总数。
- 批量选择只处理启用权限叶节点，已分配的停用权限保持锁定且不被批量操作静默移除。
- 搜索只改变可见节点，不改变批量操作的全目录范围。

## 非目标

- 不修改 Backend 权限模型、权限目录、授权依赖和保存接口。
- 不修改 OpenAPI、生成 API Client、数据库结构或权限同步流程。
- 不新增动态菜单、组织树、数据权限或 ABAC 能力。
- 不改变角色创建、编辑、删除和批量状态操作。

## 现状分析

- 当前 `buildPermissionTree` 已建立稳定业务分组，并把未知前缀放入“其他权限”。
- 当前表单值和保存请求均为 `permission_codes: string[]`，可以直接改由受控 Tree `checkedKeys` 驱动。
- 当前提交前过滤能够移除内部分组 key、未知权限码和重复值，应继续复用。
- 停用权限叶节点已经禁用；批量操作需要显式保留当前已选的停用权限，保持既有锁定语义。
- Tree 官方组件没有内置全选和反选工具栏，需要根据完整启用权限集合计算。

## 方案设计

1. 将 `TreeSelect` 替换为弹窗内直接渲染的 Ant Design `Tree`，启用 `checkable`、父子关联、整行布局和固定高度滚动。
2. 表单继续保存真实权限码数组，Tree 的 `checkedKeys` 由 `Form.useWatch` 受控同步。
3. 搜索框按分组名称、权限名称和权限码过滤；命中叶节点时保留父级，命中分组时展示该组全部叶节点。
4. 全选选择全部启用叶节点；反选对完整启用叶节点集合取补集；清空只清除启用叶节点。
5. 三种批量选择均保留当前已选的停用权限；保存时继续通过当前后端目录过滤。
6. 工具栏显示“已选启用数 / 启用总数”，并提供展开全部、收起全部图标按钮与 Tooltip。
7. 搜索时自动展开可见分组，清除搜索后保留当前展开状态。
8. 更新测试源码，覆盖过滤、批量选择、停用权限保留、直接树展示和保存请求。

## 风险与回滚

- 风险：Tree 的父节点 key 混入表单并被提交。
- 控制：`onCheck` 和提交前都按后端权限目录过滤，只保留真实权限码。
- 风险：搜索后批量操作只作用于可见节点，造成用户误判。
- 控制：全选、反选和清空始终基于完整启用权限目录，搜索只影响展示。
- 风险：批量操作移除已分配的停用权限。
- 控制：批量选择函数显式保留当前已选停用权限，并增加纯函数测试源码。
- 风险：权限数量增长导致弹窗过高或页面抖动。
- 控制：工具栏尺寸固定，Tree 使用稳定最大高度和纵向滚动。
- 回滚：恢复上一检查点的 TreeSelect 弹窗，不涉及后端、契约和数据回滚。
