## 关联需求

- `BASE-API-005`：审查公开契约的破坏性影响。
- `BASE-OPS-004`、`BASE-OPS-008`：契约门禁一致性与 Fail Closed。

## 目标、范围与现状

现有 Backend PR 工作流通过固定版本 oasdiff Action 比较目标分支与 PR 契约，保持 `fail-on: ERR` 和 `review: false`，但没有已审查破坏性变更的登记入口。本任务增加有期限、有计划关联、限定方法、路径和完整错误描述的受控例外。

本任务不改变产品需求、公开契约、应用代码、数据库或部署行为；不授权提交、推送、发布或远端工作流触发。保留任务开始时 Admin 规则和工程文档的已有修改。

## 方案与约束落实

当前 Action 固定版本的 Dockerfile 使用 oasdiff v1.28.0。官方 `checker/api_change.go` 按路径、方法和完整错误描述进行忽略匹配，并转换为小写；`checker/ignore.go` 不专门跳过注释。因此使用 `.oasdiff-exceptions.json` 作为唯一登记来源，通过 Node 轻量校验生成工作区 `temp/` 内的纯文本忽略清单，使用容器 Action 可见的相对路径，不将元数据和注释交给工具作为规则。`temp/` 沿用现有 Git 忽略规则。

每项例外登记标识、计划、负责人、批准日期、到期日期、原因、消费者迁移、发布顺序、回滚、清理安排及精确诊断。批准真实性由计划与 Code Owner 评审确认，字段存在不代表机器完成业务审批。日期按 UTC 计算，到期当日即拒绝；初始清单为空。

## 风险与回滚

- 忽略会降低已登记范围的自动拦截，需要评审真实迁移证据；同 PR 类型检查不证明旧浏览器或独立部署消费者安全。
- 原生工具匹配会忽略大小写，完整文本仍可能存在语义交叠；登记不得拼接多项诊断，升级 Action 时重新核验行为。
- 例外合并后尽快移除，永久计划保留审查证据；到期阻断促使清理，不自动延期。
- 回滚本次新增门禁接线及配套资产即可恢复无例外的严格比较，不修改契约、业务或 Git 历史。
