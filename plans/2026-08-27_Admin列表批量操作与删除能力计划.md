# Admin 列表批量操作与删除能力计划

## 当前状态和结果

- 状态：已结束
- 结果：用户、管理员、角色和文件资产普通数据列表均具备受权限控制的批量操作；安全日志保持只读，资产批量硬删除、管理端点权限强制规则和长期列表治理文档已经完成。

## 关联需求

- `BASE-BE-004`：用户账户批量状态变更与软删除继续遵守账户生命周期和会话失效边界。
- `BASE-BE-005`：管理员与角色批量操作继续经过 RBAC、二次确认和服务端授权。
- `BASE-BE-010`：新增 Admin 管理端点在 Router 显式声明资源权限，权限目录变化通过受控流程同步。
- `BASE-ADMIN-003`：补齐用户、管理员和角色管理的通用批量操作入口。
- `BASE-ADMIN-004`：批量操作覆盖选择、确认、成功、失败、无权限和危险操作状态。
- `BASE-ADMIN-005`：列表适合筛选、比较和重复操作，并在分页与窄屏下保持稳定。
- `BASE-ADMIN-006`：Admin 只通过共享 API Client 和统一 HTTP 管道消费后端契约。
- `BASE-ADMIN-007`：非日志数据列表提供与实体生命周期一致的批量选择和批量操作，日志例外保持只读。
- `BASE-API-003`：后端批量接口、根 OpenAPI、生成客户端和 Admin 消费按固定顺序同步。
- `BASE-SEC-004`：批量删除具有明确目标核对、全有或全无事务和危险操作确认。
- `BASE-SEC-006`：批量状态变更和删除继续形成可关联操作者、目标集合与请求的审计记录。

## 背景

Admin 当前存在三个顶级业务数据列表页：用户、管理员和角色。管理员列表已经支持行选择、批量启用和批量停用；用户列表没有行选择或批量操作；角色列表只有单条硬删除，没有行选择或批量操作。

安全日志页中的登录事件、审计事件和请求元数据属于按保留策略管理的安全与观测事实，不应提供人工批量删除。系统状态页不是数据列表。文件资产后端已有列表与单条硬删除接口，但 Admin 当前没有文件资产列表页，Backend 也没有资产批量硬删除接口。

用户要求现有非日志类列表页统一具备批量选择和批量操作。实体已有软删除时对接软删除，已有硬删除时提供批量硬删除；后端缺少相应接口时明确补齐。

第一阶段完成后，用户进一步明确：新增管理端 API 端点必须具有显式权限；文件资产需要完善列表查询与批量硬删除 API，并在 Admin 增加资产列表、单条操作和批量操作；日志记录类数据不增加批量操作或删除；该规则需要进入项目长期规则和权威文档。

## 目标

1. 用户列表增加受控的行选择，并提供批量启用、批量停用和批量软删除。
2. 管理员列表完整保留现有行选择、批量启用和批量停用，不增加删除入口。
3. 角色列表增加行选择，并提供批量启用、批量停用和批量硬删除。
4. 所有批量写操作由 Backend 提供专用端点，在单一事务中全有或全无完成，禁止前端循环调用单条接口。
5. 批量停用和批量删除继续使用二次确认、服务端权限、会话撤销、资源状态检查和审计链。
6. 操作成功后清空选择并刷新列表；失败时保留选择并展示明确错误，不返回部分成功或假成功。
7. 根 OpenAPI、生成 API Client、Admin API 适配层和页面消费保持一致。
8. 完善资产列表查询条件，增加资产批量硬删除端点，并在 Admin 增加受权限控制的资产列表、单删和批量删除能力。
9. 新增 Admin 管理端 API 端点必须声明明确 `PermissionCode`，客户端入口权限与服务端最终授权保持一致。
10. 把“非日志数据列表必须支持批量操作、日志列表保持只读、删除语义匹配实体生命周期”写入产品需求、Admin 与 Backend 规则及详细工程标准。

## 非目标

1. 不为登录事件、审计事件和请求元数据增加选择列、人工批量删除或绕过保留策略的清理入口。
2. 不修改系统状态页，因为该页面不承载可操作数据列表。
3. 不为管理员增加软删除字段、硬删除端点或批量删除。管理员既有生命周期明确使用启用和停用管理，保留历史会话、角色关系、资产上传者和安全追溯标识。
4. 不允许选择当前登录管理员，也不弱化最后一名启用超级管理员保护。
5. 不改变普通用户自助注销接口、日志保留脚本、Web、部署配置或生产数据。
6. 不引入跨页全选、按筛选条件全量操作或后台异步批处理；本次只处理当前已加载页中明确选中的有限 ID 集合。
7. 不为资产增加软删除、恢复、在线编辑或上传入口；资产继续使用现有硬删除和存储补偿语义，上传继续由既有双域组件承担。

## 现状分析

1. `UsersPage` 使用分页 `ProTable`，已有单条启用、停用、资料更新、密码重置和会话管理，没有 `rowSelection`。
2. `User.deleted_at` 已表达软删除，用户查询默认排除已删除记录；用户自助注销会匿名化用户名和邮箱、停用账户、提升凭据版本、设置删除时间并撤销会话。
3. Backend 当前只有单条用户状态接口，没有管理端用户批量状态或批量软删除接口，也没有独立 `users:delete` 权限与确认动作。
4. `AdminsPage` 已有受控选择列和批量启停；Backend 已有原子批量状态接口，并保护当前管理员和最后启用超级管理员。
5. 既有已确认计划明确管理员生命周期只使用状态停用，不提供删除。`Admin` 没有 `deleted_at`，管理员会话使用限制删除外键，历史身份还需要服务于安全追溯。
6. `RolesPage` 无选择列；Backend 只有删除单个未使用角色的硬删除接口。角色已有 `is_active`，但没有批量状态接口。
7. 角色硬删除前会检查角色是否仍关联管理员。批量删除需要锁定目标集合并在任一角色被使用、缺失或重复输入时整批失败。
8. 权限目录由源码定义并通过同步脚本写入数据库。新增用户删除权限需要更新源码目录、契约测试与权限同步检查，但不需要 Alembic 迁移。
9. 资产列表端点已有 `assets:read` 权限，单条删除已有 `assets:delete` 权限、`assets:delete` 二次确认、审计和文件暂存删除补偿。
10. 资产列表当前只支持页码和每页数量，不支持文件名、场景或上传主体类型筛选；Admin 尚无 `/assets` 路由、Access 映射和资产页面。
11. 资产删除同时修改 PostgreSQL 元数据和存储文件。批量删除需要先固定顺序锁定并验证全部资产，再把全部文件暂存到私有 trash；任一步失败时恢复已经暂存的文件并回滚数据库，提交后逐个清理 trash。
12. 当前长期规则只要求 Admin 页面覆盖完整状态和 Backend 默认拒绝授权，尚未明确规定非日志列表必须有批量能力，也未明确禁止新增 Admin 管理端点缺少独立权限代码。

## 方案设计

### 统一批量请求契约

1. 为用户和角色分别定义批量状态请求，字段为 UUID 列表和目标 `is_active` 状态。
2. 为用户和角色分别定义批量删除请求，字段为 UUID 列表。
3. 每次请求至少包含 1 个、最多包含 100 个目标，重复 ID 在请求校验阶段拒绝，不静默去重。
4. 成功响应返回实际完成数量和目标 ID 集合，便于 Admin 准确反馈；失败使用现有统一错误模型。
5. 批量端点使用稳定、可生成的公开 Schema，不在 Admin 手写 DTO。

### 用户批量状态与软删除

1. 增加管理端用户批量状态端点，复用 `users:update` 权限；批量停用消费 `users:disable` 二次确认，批量启用保持现有低风险语义。
2. Service 按固定 ID 顺序锁定全部目标用户，验证记录全部存在且未删除，再统一修改状态。
3. 实际状态发生变化时提升各用户凭据版本并撤销其全部 Web 会话；整批操作写入审计。
4. 增加 `users:delete` 权限、`users:delete` 二次确认动作和管理端批量软删除端点。
5. 批量软删除复用普通用户自助注销的核心数据语义：匿名化用户名、清空邮箱和显示名称、停用账户、提升凭据版本、设置 `deleted_at` 并撤销全部 Web 会话。
6. 匿名化标识继续基于用户 UUID 生成，满足用户名唯一约束；任一目标缺失或已删除时整批失败。
7. 用户软删除不物理删除用户、会话或安全记录，不提供恢复入口。

### 管理员批量状态

1. 保留现有 `rowSelection`、批量启用、批量停用、当前管理员禁选和权限控制。
2. 本次只统一交互细节、成功清空选择和失败保留选择，不改变 Backend 既有批量接口语义。
3. 管理员不增加删除操作。离职、撤权和阻止登录继续通过停用完成，历史身份与安全追溯关系继续保留。

### 角色批量状态与硬删除

1. 增加角色批量状态端点，复用 `roles:update` 权限。批量停用使用新的 `roles:status:change` 二次确认动作，批量启用保持低风险语义。
2. Service 按固定 ID 顺序锁定目标角色，确认全部存在后统一更新 `is_active`；实际变化时撤销受影响管理员的会话并写入审计。
3. 增加角色批量硬删除端点，复用 `roles:delete` 权限和 `roles:delete` 二次确认动作。
4. 删除前在同一事务中确认每个角色都未关联管理员；任一角色被使用或不存在时整批失败。
5. 硬删除依赖现有角色权限关联的数据库级联语义，禁止越过管理员关联的限制删除边界。

### 资产列表与批量硬删除

1. 扩展现有 `GET /api/v1/assets`，增加文件名搜索、场景和上传主体类型筛选，继续使用 `assets:read` 权限与统一分页响应。
2. 在资产领域定义独立的批量删除请求与结果 Schema，每次接受 1 至 100 个唯一资产 UUID；新增 `DELETE /api/v1/assets/batch`，声明 `assets:delete` 权限并复用 `assets:delete` 二次确认动作。
3. Repository 按资产 UUID 固定顺序锁定完整目标集合。任一资产缺失时整批拒绝，禁止只删除存在的子集。
4. Service 在单一审计事务内依次把全部目标文件暂存到私有 trash，并删除全部元数据。任一文件暂存、数据库写入或审计步骤失败时，按相反顺序恢复已暂存文件并回滚元数据。
5. 数据库与审计提交后逐个清理 trash；清理失败继续保留私有 trash 并记录可定位的严重日志，不能把已提交删除伪装成失败后重试整个请求。
6. 单条删除继续保留，内部实现与批量删除共享同一补偿编排，避免单删和批量删除产生不同的一致性语义。

### Admin 页面交互

1. 用户、角色和资产 `ProTable` 使用受控 `rowSelection`，选择状态使用页面本地状态，翻页或查询条件变化时清空选择，避免对不可见记录误操作。
2. 选择列只在当前管理员具有至少一项相应批量写权限时显示；无权限时不制造不可用的选择体验。
3. 使用 ProTable 原生批量提示区显示已选数量，并按权限提供批量启用、批量停用和批量删除按钮。
4. 批量删除使用危险按钮和清晰文案，确认窗口明确显示数量、删除语义和不可恢复边界；软删除文案说明账户将匿名化且不能登录。
5. 批量状态与删除分别绑定准确二次确认动作，一次 Token 只消费一次。
6. 请求进行中禁用重复提交；成功后提示实际数量、清空选择、刷新列表，失败后保留选择并使用统一错误反馈。
7. 保留所有现有单条操作、筛选、分页、列设置、权限判断、操作列样式和窄屏滚动行为。
8. Admin 增加 `/assets` 路由和 `canAssets` Access 映射。资产列表展示可识别的图片缩略图或文件图标、原始文件名、场景、真实 MIME、文件大小、上传主体、创建时间，并提供打开文件、复制地址和单条删除。
9. 资产筛选使用 URL 或页面查询状态驱动 Backend 参数，筛选、重置和翻页均清空当前选择；只读管理员可以查看与打开资产，不显示选择列和删除入口。

### 权限、审计与事务

1. 客户端权限只控制入口可见性，Backend 对每个 Admin 管理端点执行最终权限和 CSRF 校验。新增管理端点必须在 Router 显式声明准确 `PermissionCode`，缺少权限目录项时先补目录、同步检查和契约测试，禁止使用通用登录态代替资源权限。
2. 删除与批量停用属于高风险操作，必须经过动作绑定、Session 绑定、一次性的管理员二次确认 Token。
3. 批量操作使用一个数据库事务、固定锁顺序和单条审计意图；`changed_fields` 记录目标数量、目标 ID 摘要和变更类型，不记录敏感资料。
4. 任一目标校验失败、会话撤销失败或审计失败时回滚整批数据库变更，明确返回失败。
5. 双域上传端点继续按 Web 或 Admin Cookie Profile、Origin、CSRF、上传主体和场景策略授权，不属于 Admin 管理端点权限目录；本规则不改变用户上传契约。

### 长期规则与权威文档

1. 在 `docs/PROJECT_REQUIREMENTS.md` 增加产品验收项：Admin 中除登录安全事件、审计事件、请求元数据等保留策略日志外，所有数据列表必须支持按权限显示的批量选择和至少一种与实体生命周期一致的批量操作。
2. 在 `apps/admin/AGENTS.md` 增加强制 UI 规则：新增或修改数据列表时必须核对选择、批量操作、权限显隐、成功清理、失败保留、分页和筛选切换；日志列表明确只读且不提供选择或删除。
3. 在 `apps/backend/AGENTS.md` 增加强制 API 规则：新增 Admin 管理端点必须具有显式权限；批量写端点必须使用专用批量 API、1 至 100 个唯一 ID、固定锁顺序、单事务全有或全无，并按风险接入确认和审计。
4. 在 `docs/architecture/admin-engineering-standard.md` 保存列表页面分类、标准交互和验收矩阵；在 `docs/architecture/authentication-authorization.md` 保存管理端点权限与批量高风险操作边界。
5. 在 `docs/architecture/file-asset-storage.md` 保存资产批量删除的文件暂存、反向恢复、数据库提交和提交后清理顺序。

## 实施顺序

1. 第一阶段用户与角色批量能力已按原确认范围完成并保留。
2. 用户确认第二阶段扩展范围后，把计划状态更新为“实施中”并记录确认。
3. 更新产品需求、Admin 与 Backend 规则及详细工程标准，先固化管理端点权限和非日志列表批量能力的验收边界。
4. 扩展资产 Repository、Schema 和列表查询，增加固定锁顺序的批量目标读取与筛选条件。
5. 重构资产单删并实现批量硬删除 Service，完整处理多文件暂存、事务回滚恢复、审计和提交后清理。
6. 增加受保护资产批量 Router 端点，显式声明 `assets:delete`、CSRF 和 `assets:delete` 二次确认。
7. 增加 Backend 测试源码，覆盖重复 ID、缺失目标、文件暂存失败、数据库失败、恢复失败、提交成功和 trash 清理失败；测试命令只在用户明确授权后运行。
8. 导出根 `openapi.json`，运行 `pnpm generate-api`，确认重复生成无差异。
9. 扩展 Admin API 适配层、Access 和路由，实现资产筛选列表、预览、地址复制、单删和批量删除。
10. 更新 MSW Handler、Access 测试和资产页面组件测试源码；Vitest 只在用户明确授权后运行。

## 风险与回滚

- 风险：批量软删除会一次性匿名化多个账户且不提供恢复。通过最多 100 项限制、危险文案、二次确认、显式 ID 和单事务控制。
- 风险：前端循环单条接口会产生部分成功。只使用 Backend 专用批量端点，任一失败整批回滚。
- 风险：批量角色停用可能影响当前管理员权限。状态变化后撤销关联管理员会话，使新权限状态及时生效。
- 风险：批量角色删除包含仍被使用的角色。删除前锁定并逐个核对管理员关联，任一冲突整批拒绝。
- 风险：权限目录新增 `users:delete` 后数据库尚未同步。权限同步检查必须明确失败并提示运行受控同步步骤，应用不自动改库。
- 风险：分页选择残留导致操作不可见记录。页码、搜索或数据刷新改变时清空选择。
- 风险：公开契约与 Admin 类型漂移。严格按 Backend、OpenAPI、API Client、Admin 顺序实施并检查生成幂等。
- 风险：资产批量硬删除跨 PostgreSQL 和文件系统，无法获得单一原生事务。通过全部目标锁定、文件私有暂存、失败反向恢复、数据库审计事务和提交后清理建立可补偿一致性；恢复失败必须返回“需要人工核查”并记录目标资产。
- 风险：批量删除大量文件会放大文件系统 I/O 和恢复成本。继续限制每次最多 100 项，顺序执行存储变更并禁止后台静默重试删除请求。
- 风险：把日志只读例外写得过宽会掩盖普通业务列表缺失批量能力。例外只允许登录安全事件、审计事件、请求元数据及经产品需求明确登记的不可变历史记录，普通业务记录不能自行归类为日志。
- 风险：新增管理端点遗漏权限会形成越权入口。Router 必须显式声明权限代码，并由权限目录测试、OpenAPI 审计和 Admin Access 映射共同检查。
- 回滚：在未执行生产数据操作的前提下精确恢复 Backend、契约和 Admin 代码；用户软删除和角色硬删除一旦已对真实数据执行，代码回滚不能恢复数据，生产使用前必须另行验证备份与操作授权。
