# Admin 文件资产上传主体标识精简计划

## 关联需求

- `BASE-ADMIN-005`：管理界面保持紧凑、可扫描，适合高频工作操作。
- `BASE-QUAL-002`：修改时保护已有功能和 UI 行为。

## 背景

Admin 文件资产页“上传主体”列当前分两行展示主体类型和完整上传主体 UUID。完整 UUID 占用较多横向空间，影响列表扫描；业务操作只需要识别主体类型，并在排障时能够复制主体 ID。

## 目标

- 存在 `uploader_id` 时只显示上传主体类型，不显示 UUID 文本。
- 在上传主体类型后显示复制图标，点击后复制完整 `uploader_id`。
- 复制图标提供 Tooltip、无障碍名称和成功或失败反馈。
- 不存在 `uploader_id` 时保留现有“系统任务”信息。

## 非目标

- 不修改上传主体类型、资产数据、筛选条件和 API 契约。
- 不增加上传主体详情页面或跳转入口。
- 不调整其他表格列、图片预览、复制文件地址和删除操作。

## 现状分析

- 页面位于 `apps/admin/src/features/assets/AssetsPage.tsx`。
- 当前通过 `Typography.Text code copyable` 直接展示并复制 `uploader_id`。
- 页面已有剪贴板写入和 Ant Design 成功或失败消息模式，可沿用同一交互。
- `CopyOutlined`、`Button` 和 `Space` 已在页面使用，只需补充 `Tooltip`。

## 方案设计

1. `uploader_id` 存在时，使用不换行的水平 `Space` 显示主体类型和复制图标按钮。
2. 复制按钮使用 `CopyOutlined`，Tooltip 与 `aria-label` 均命名为“复制上传主体 ID”。
3. 点击按钮调用剪贴板 API，成功提示“上传主体 ID 已复制”，失败继续走统一错误消息。
4. `uploader_id` 不存在时保留主体类型及“系统任务”文本。
5. 更新现有组件测试源码，约束 UUID 不可见、复制入口存在且可执行；是否运行 Vitest继续遵守用户单独授权边界。

## 风险与回滚

- 风险：仅使用图标可能降低功能可发现性，剪贴板权限失败时可能没有复制结果。
- 控制：提供 Tooltip、无障碍名称及明确成功或失败反馈；完整 UUID 仍来自原始数据，不改变契约。
- 回滚：恢复当前 `Typography.Text code copyable` 的 UUID 展示，不影响资产数据。
