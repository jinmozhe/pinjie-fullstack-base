# 本地检查点提交与高风险编辑治理计划

## 1. 当前状态和结果

- 状态：已结束
- 结果：已完成

## 2. 关联需求

- 无。本计划属于 AI 辅助开发与文件恢复能力治理，不改变产品功能或验收边界。

## 3. 背景

当前规则要求文本文件采用 UTF-8 无 BOM、批量替换后复读具体行，并将 Git 提交视为独立授权动作，但尚未明确可恢复检查点与高风险整文件写入之间的前置关系。需要在不扩大 Git 授权的前提下，建立可执行的恢复基线和安全写入流程。

## 4. 目标

1. 为完成并通过轻量验证的独立功能单元建立本地检查点提交建议与授权规则。
2. 对批量覆盖、整文件重写和跨文件机械修改增加可恢复基线、严格错误处理、写前校验和写后复读要求。
3. 保持提交、推送、发布和部署的独立授权边界。
4. 将长期强制约束、详细操作步骤、索引和交付记录同步到各自权威来源。

## 5. 非目标

- 不自动提交、推送、创建 Pull Request、发布或部署。
- 不修改应用源码、API、数据库、生成契约或运行行为。
- 不把用户无关修改混入检查点提交。
- 不用检查点提交替代安全编辑和验证。

## 6. 现状分析

- 根 `AGENTS.md` 已规定 Git 动作必须独立授权，但没有描述何时应主动请求检查点提交。
- 根 `AGENTS.md` 已规定批量替换后复读，但没有禁止在缺少可恢复基线时对含未提交修改的目标执行整文件覆盖。
- `docs/operations/ai-assisted-development-workflow.md` 已维护实施、验证、交付和 Git 授权流程，适合承载详细步骤。

## 7. 方案设计

- 根规则增加“本地检查点与高风险编辑”章节，保存跨仓库目录生效的长期边界。
- AI 协作流程文档增加检查点请求、高风险写入、精确暂存和恢复验证的执行顺序。
- 完成功能单元后立即请求本地提交授权；获得当前任务的分阶段检查点授权后，在每个功能单元验证完成时立即精确暂存并提交。
- 目标文件包含未提交修改且缺少可恢复基线时，禁止用脚本整文件覆盖；改用逐文件 `apply_patch`，或先取得检查点提交授权。

- 风险：规则可能被误解为自动 Git 授权。通过同时保留独立授权和精确暂存约束消除歧义。

- 回滚：通过普通 Git 差异回退本次文档修改，不删除或重命名计划文件。
