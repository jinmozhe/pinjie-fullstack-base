## 3. 背景

当前母版后端的日志系统基于 Loguru 实现，默认仅配置了输出到控制台/终端（`sys.stderr`）的 Sink。虽然这满足了云原生容器环境通过标准输出收集日志的要求，但在本地开发、单机调试或非容器化排障时，开发者和运维人员经常需要直接在本地文本编辑器中查看历史日志文件。

同时，日志文件落盘需要避免磁盘占满、主线程阻塞、中文乱码和日志无限增长等运维隐患，因此需要引入 Loguru 内置的异步队列（`enqueue=True`）、按大小/时间轮转（`rotation`）、自动过期清理（`retention`）以及自动压缩（`compression="zip"`），并将这些策略通过 `.env` 环境变量进行集中管理。

## 4. 目标

1. **环境受控配置化**：在 `apps/backend/app/core/config.py` 中新增 `LOG_FILE_ENABLED`、`LOG_FILE_PATH`、`LOG_FILE_ROTATION`、`LOG_FILE_RETENTION` 等环境变量，可在 `.env` 中按需开关和调整。
2. **异步零阻塞落盘**：在 `apps/backend/app/core/logging.py` 中增加文件 Sink，使用 `enqueue=True` 确保磁盘写 I/O 运行在后台独立线程，主业务 API 请求耗时零损耗。
3. **全自动请求拦截**：利用现有 `request_context_middleware`，无需在业务代码中手动侵入，自动为每个 HTTP 请求记录方法、路由、状态码、耗时、`request_id` 与 `trace_id` 到日志文件。
4. **运维安全兜底**：
   - 默认启用 50MB 自动切分（`rotation="50 MB"`）。
   - 默认保留 10 天历史日志（`retention="10 days"`），过期自动删除，绝不撑爆硬盘。
   - 切分后的历史日志自动压缩为 `.zip` 文件，节省 90% 存储空间。
   - 强制使用 `encoding="utf-8"`，杜绝 Windows 与 Linux 乱码。
5. **资产与版本安全**：更新 `.gitignore` 与 `apps/backend/.gitignore`，确保 `logs/` 目录下的具体日志文件被 Git 忽略，不被意外提交入库。
6. **门禁与测试保障**：补充针对日志配置开关、文件写入与轮转策略的单元测试，确保全后端测试覆盖率持续达标（>= 90%）。

## 5. 非目标

- 不改变现有控制台标准输出（`sys.stderr`）的行为。
- 不影响基于 Redis Stream 的高性能请求元数据流水线（`request_logs` 表）。
- 不在前端（Admin/Web）引入日志文件下载或在线查看功能（属于派生系统运维能力）。
- 不破坏容器化部署环境的只读文件系统兼容性（容器内可通过 `LOG_FILE_ENABLED=false` 保持纯 stdout 模式）。

## 6. 现状分析

| 维度 | 当前实现 | 升级目标 |
| --- | --- | --- |
| 配置项定义 | `Settings` 仅有 `log_level`（默认 INFO） | 增加 `log_file_enabled`、`log_file_path`、`log_file_rotation`、`log_file_retention` |

| Git 忽略规则 | 根 `.gitignore` 已包含部分常规项 | 显式声明 `logs/` 与 `*.log` 忽略规则 |

## 7. 方案设计

### 7.1 配置项设计（`config.py`）

在 `apps/backend/app/core/config.py` 的 `Settings` 类中增加配置字段：

```python
log_file_enabled: bool = Field(default=True, validation_alias="LOG_FILE_ENABLED")
log_file_path: str = Field(default="logs/app_{time:YYYY-MM-DD}.log", validation_alias="LOG_FILE_PATH")
log_file_rotation: str = Field(default="50 MB", validation_alias="LOG_FILE_ROTATION")
log_file_retention: str = Field(default="10 days", validation_alias="LOG_FILE_RETENTION")
```

在 `apps/backend/.env.example` 中补充公开模板：

```ini
# 日志文件持久化配置
LOG_FILE_ENABLED=true
LOG_FILE_PATH=logs/app_{time:YYYY-MM-DD}.log
LOG_FILE_ROTATION=50 MB
LOG_FILE_RETENTION=10 days
```

### 7.2 日志引擎配置（`logging.py`）

在 `apps/backend/app/core/logging.py` 中更新 `configure_logging` 函数：

```python
def configure_logging(settings: Settings) -> None:
    logger.remove()

    # 1. 终端与容器标准错误流输出
    logger.add(
        sys.stderr,
        level=settings.log_level,
        serialize=settings.environment == "production",
        backtrace=False,
        diagnose=False,
        enqueue=False,
    )

    # 2. 本地文件异步落盘 Sink（受环境变量控制）
    if settings.log_file_enabled and settings.log_file_path:
        logger.add(
            settings.log_file_path,
            level=settings.log_level,
            rotation=settings.log_file_rotation,
            retention=settings.log_file_retention,
            compression="zip",
            encoding="utf-8",
            enqueue=True, # 异步后台线程写入，零阻塞业务请求
            backtrace=False,
            diagnose=False,
        )
```

### 7.3 日志格式与信息沉淀

日志格式继承 Loguru 默认的高可读格式，中间件自动记录的内容包含：

- 请求时间（毫秒精度）。
- 日志级别（`INFO` / `WARNING` / `ERROR`）。
- 模块与函数位置。
- HTTP 动词、请求路由模板、HTTP 状态码、精确耗时（毫秒）。
- 结构化绑定的 `request_id` 与 `trace_id`。

## 11. 风险与回滚

| 风险 | 影响 | 预防措施 | 回滚方案 |
| --- | --- | --- | --- |
| 容器环境只读文件系统报错 | 容器无法创建 `logs/` 目录导致启动失败 | 配置默认为 `LOG_FILE_ENABLED=true`，但在容器内可通过环境变量注入 `LOG_FILE_ENABLED=false` 禁用文件输出 | 环境变量关闭文件日志或回退代码提交 |
| Windows 路径反斜杠转义 | 路径解析异常 | 统一使用 POSIX 风格正斜杠路径（`logs/app_...`） | 统一路径格式转换 |
| 磁盘空间占用 | 极端情况下磁盘增长 | 严格配置 50MB 切分、10 天清理与 zip 压缩 | Loguru 内置自动清理机制 |
