# Browser E2E 人工触发与发布解耦计划

## 当前状态和结果

- 状态：已结束
- 结果：已完成

## 关联需求

- 无。本计划调整现有 CI 和镜像发布门禁的触发策略，不改变产品能力。

## 背景

当前 `CI - Browser E2E` 会在每次 Push 和 Pull Request 自动运行，`Publish Images` 还要求目标 Commit SHA 存在成功的 E2E Push Run。该流程执行时间和环境准备成本较高，不符合当前项目以本地 E2E 为主、线上按需复核的使用方式。

2026-08-21，用户明确要求保留 Browser E2E 工作流文件并改为人工触发，同时让镜像发布完全取消对 E2E 运行记录的依赖。

## 目标

1. `CI - Browser E2E` 只通过 GitHub Actions 人工触发。
2. `Publish Images` 只要求 Governance、Backend、Frontend 和 Security 四个自动 Push 工作流成功。
3. 保留现有 Playwright、PostgreSQL、Redis 和跨栈执行步骤，便于需要时人工复核。
4. 同步发布、测试和 Actions 文档，明确 E2E 不再属于线上自动门禁或镜像发布前置条件。

## 非目标

- 不删除 `.github/workflows/ci-e2e.yml`。
- 不删除或弱化本地 Playwright 测试。
- 不修改 Backend、Admin、Web、API Client 或数据库实现。
- 不触发镜像发布、生产部署或 E2E 线上运行。

## 现状分析

- `.github/workflows/ci-e2e.yml` 当前监听 `push` 和 `pull_request`。
- `.github/workflows/publish-images.yml` 当前逐项查询五个 Push 工作流，包含 `ci-e2e.yml`。
- 发布手册和 Actions 说明当前都把 Browser E2E 记录为自动门禁和发布前置条件。
- 测试策略当前声明 Pull Request 默认运行 Playwright Chromium，需要调整为本地执行、线上人工按需复核。

## 方案设计

1. 将 Browser E2E 的触发器改为 `workflow_dispatch`，不增加自动触发条件。
2. 从 Publish Images 的源工作流校验列表中删除 `ci-e2e.yml`，继续保留其余四项失败关闭校验。
3. 更新权威文档中的流程图、触发表、使用场景、失败说明和检查清单。
4. 将 E2E 定位调整为本地常规验证和 GitHub 人工复核能力，不作为镜像发布门禁。
