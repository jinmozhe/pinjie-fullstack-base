## 关联需求

- `BASE-BE-004`：把 Admin 软删除用户从限期恢复调整为永久可恢复，恢复后继续保持停用。
- `BASE-ADMIN-003`：用户管理回收站继续提供受权限控制的单条和批量恢复。
- `BASE-ADMIN-004`：移除误导性的恢复截止展示，保留清晰的可恢复和不可恢复状态。
- `BASE-ADMIN-006`：Admin 继续只消费根 OpenAPI 生成的 API Client 类型。
- `BASE-API-003`：Backend、根 OpenAPI、生成客户端和 Admin 同步交付。
- `BASE-API-005`：移除公开响应字段时，在同一计划中完成 Admin 消费者迁移。
- `BASE-SEC-006`：删除与恢复继续保留权限、会话撤销和审计边界。

## 背景

当前 Admin 管理员软删除用户后，系统按 `USER_RECYCLE_BIN_RETENTION_DAYS` 计算恢复截止时间，默认 30 天，并通过 `anonymized_at` 区分已不可恢复的匿名化记录。产品策略现调整为所有用户统一使用软删除，不再提供匿名化功能，回收站中的软删除用户长期可恢复。

## 目标

1. 建立项目统一的 `SoftDeleteMixin`，软删除模型使用 `deleted_at`、`deleted_by_id`、`deleted_by_type` 和可选 `deletion_reason`。
2. 所有软删除流程长期可恢复，不再受恢复截止时间或匿名化状态限制。
3. Admin 回收站移除“恢复截止”列，继续显示删除时间、删除主体和可选删除原因。
4. 用户自助注销与管理员删除统一走软删除流程，恢复后用户仍保持 `is_active=false`。
5. 删除原因在单条和批量删除时均可输入，允许为空，默认值为 `null`。
6. 移除 `anonymized_at`、30 天回收站配置、到期匿名化脚本及相关运维步骤。
7. 同步产品需求、架构说明、OpenAPI、API Client、Admin 测试源码、索引和变更日志。

## 非目标

1. 不把恢复操作改成自动启用，启用仍由 `is_active` 单独控制。
2. 不为 `SoftDeleteMixin` 增加管理员专属外键；删除主体使用通用 ID 和主体类型。
3. 不改变管理员、角色、资产、安全日志和会话的既有专属生命周期，只有明确采用软删除的模型继承 Mixin。
4. 不执行真实数据库迁移、目标环境权限同步、发布或部署。

## 现状分析

1. `User.is_active` 与 `User.deleted_at` 是两个独立语义，前者控制可用性，后者表示软删除状态。
2. `User` 当前继承 `UUIDPrimaryKeyMixin`、`TimestampMixin` 和 SQLAlchemy `Base`，尚未使用软删除 Mixin。
3. `deleted_at` 非空表示记录处于回收站；用户删除时应同时写入删除主体和主体类型。
4. `restore_expires_at` 和 `can_restore` 是 Service 计算后写入响应的字段，不是数据库列；永久恢复后移除 `restore_expires_at`。
5. `anonymized_at` 当前用于标记不可逆匿名化，本次需求要求删除该字段及其所有流程。
6. 管理员和用户自助软删除记录都会继续占用用户名和邮箱唯一值，永久保留意味着这些标识不会自动释放。
7. `deleted_by_admin_id` 只能表达管理员删除，不能作为通用字段；应迁移为 `deleted_by_id` 与 `deleted_by_type`。
8. 删除字段具有条件一致性：正常记录的三个删除字段都为空，软删除记录的三个字段都非空；`deletion_reason` 可以为空。

## 方案设计

1. 新增 `SoftDeleteMixin`，字段为 `deleted_at`、`deleted_by_id`、`deleted_by_type` 和可空 `deletion_reason`；Mixin 不包含 `is_active` 或隐私匿名化字段。
2. `deleted_at`、`deleted_by_id`、`deleted_by_type` 在软删除状态下由 Service 自动写入；恢复时成组清空，数据库增加成组一致性检查。
3. `deleted_by_type` 支持 `admin`、`user`、`system` 等主体类型，不建立指向 `admins` 的专属外键；完整历史仍由 `AuditEvent` 保存。
4. 删除恢复校验只检查目标是否处于软删除状态，不再检查截止时间或 `anonymized_at`。
5. 删除 `anonymized_at`、`USER_RECYCLE_BIN_RETENTION_DAYS`、到期匿名化脚本及其运维命令；用户自助注销不再改写身份资料。
6. Admin 单条和批量删除请求增加可选 `deletion_reason`，空字符串归一化为 `null`；批量请求使用一个共同原因并保持原子事务。
7. Admin 删除“恢复截止”列，保留删除时间、删除主体、删除原因和恢复入口。
8. `deleted_at` 不直接放入通用 `Base` 或 `TimestampMixin`。只有明确需要软删除的模型继承 `SoftDeleteMixin`。

## 风险与回滚

- 永久保留软删除用户会长期占用用户名、邮箱和其他资料，个人资料保留风险由访问控制、审计和备份保护承担。
- 删除 `anonymized_at`、`deleted_by_admin_id` 和恢复期限字段属于公开契约与数据库迁移变更，必须先完成数据迁移和消费者同步。
- `deleted_by_id` 使用多态主体标识，不建立管理员专属外键；主体类型必须由服务端白名单校验。
- 数据库迁移需要先备份并验证已有删除记录的字段回填，禁止直接丢弃原管理员删除主体信息。
