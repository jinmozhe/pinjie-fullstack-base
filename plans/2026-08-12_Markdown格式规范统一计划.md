# Markdown 格式规范统一计划

## 1. 当前状态

- 状态：已结束
- 结果：已完成

- 影响范围：全仓库 Markdown 文档、项目规则和编辑器协作配置

## 1.1 关联需求

`BASE-DOC-006`、`BASE-QUAL-003`。

## 2. 背景

本仓库的 Markdown 文档主要在 GitHub、VS Code 和 Obsidian 中阅读。GitHub Flavored Markdown 可以作为语法兼容基线，但当前仓库没有 markdownlint 配置，VS Code 插件只能采用自身默认规则，导致不同插件版本和不同 AI 助手对表格等源码格式产生不一致判断。

用户已选择保留 markdownlint，并通过仓库级配置关闭或调整不适合中文文档及本项目写法的规则。

## 3. 目标

1. 使用 GitHub Flavored Markdown 作为仓库 Markdown 语法基线。
2. 增加仓库级 `.markdownlint.json`，让 VS Code markdownlint 插件和 AI 使用相同格式规则。
3. 显式固定标题、列表、分隔线、代码块、强调、链接、图片和表格风格，不依赖 `consistent` 自动推断。
4. 修复现有 Markdown 中与新配置不一致的问题，使全仓库检查通过。
5. 记录 AI 编写 Markdown 时必须遵守 GFM 语法基线和仓库配置。

## 4. 非目标

1. 不安装 GitHub Markdown Preview 或其他预览插件。
2. 暂不增加 Markdown CI 工作流或合并门禁。
3. 不修改 Markdown 文档的业务内容和原有计划历史。
4. 不要求所有表格按中文视觉宽度纵向对齐。
5. 不修改用户个人 VS Code 或 Obsidian 设置。

## 5. 现状分析

1. 用户已安装 `DavidAnson.vscode-markdownlint 0.62.1`，内置 markdownlint `0.41.1` 和 markdownlint-cli2 `0.23.2`。
2. 仓库不存在 `.markdownlint.json`、`.markdownlint.jsonc` 或等价配置。
3. markdownlint 默认关闭 `MD013`，其余规则默认开启；`MD060` 会对无法归入统一表格样式的源码发出告警。
4. `plans/README.md` 模板表格中的空单元格写法与 `compact` 风格不一致。

## 6. 方案设计

1. 新建 `.markdownlint.json`，保持默认规则开启，显式固定标题、列表、分隔线、代码块、强调、链接、图片和表格风格，并只调整中文长行及不同章节同名子标题规则。
2. 在 `.vscode/extensions.json` 推荐官方 markdownlint 扩展，不新增预览插件或个人设置。
3. 在根 `AGENTS.md` 增加 Markdown 编写规则，要求遵守 GFM 和仓库 markdownlint 配置。
4. 修复全仓库 Markdown 违规，只做格式调整，不改变文档语义。
5. 更新全项目索引和 Changelog，记录新增的文档质量门禁。
6. 在仓库根目录固定支持项目 Node.js 20 基线的 `markdownlint-cli2 0.22.0`，增加统一的 `pnpm lint:md` 全仓库检查命令，并生成根 `pnpm-lock.yaml`。

## 10. 风险与回滚

1. 风险：一次性产生大量纯格式差异。控制方式是先用最小配置扫描，只修改实际违规文件。
2. 风险：配置过度放宽失去约束价值。控制方式是只调整已确认不适合中文或项目写法的规则，其余默认保持开启。
3. 风险：格式修复改变文档语义。控制方式是复读差异并运行本地链接和索引检查。
4. 回滚：通过后续普通提交调整规则或恢复格式，不改写 Git 历史。
5. 风险：VS Code 扩展和项目 CLI 的内置 markdownlint 版本不一致。已安装扩展使用 `markdownlint 0.41.1`，项目 CLI 使用 `markdownlint 0.40.0`；控制方式是两套工具共用根配置并分别扫描验证，项目升级到 Node.js 22 基线后再评估同步升级 CLI。

## 14. 实施结果

1. 新增根目录 `.markdownlint.json`，保持默认规则开启，关闭中文长行检查 `MD013`，将 `MD024` 限定为同级标题检查。
2. 显式固定 ATX 标题、`-` 无序列表、连续编号有序列表、2 空格列表缩进、`---` 分隔线、反引号围栏代码块、星号强调、行内链接和图片、首尾管道 `compact` 表格风格，不再依赖 `consistent` 自动推断。
3. 新增 `.vscode/extensions.json`，只推荐 `DavidAnson.vscode-markdownlint`，没有增加预览插件或修改个人 VS Code 设置。
4. 在根 `AGENTS.md` 增加 GFM 语法基线、显式格式写法和 AI 修改后处理告警的长期规则。
5. 为 `.agents/rules/` 的 Antigravity 特殊桥接格式增加局部 `.markdownlint.json`，继承根配置并仅关闭不适用的 `MD041`。
6. 修复 `plans/README.md` 的空表格单元格和 `docs/architecture/project-structure.md` 的两处列表空行，不改变文档语义。
7. 使用 VS Code 插件对应的 `markdownlint-cli2 0.23.2` 和 `markdownlint 0.41.1` 扫描全仓库 34 份 Markdown，结果为 0 个问题。
8. 在根 `package.json` 固定项目级 `markdownlint-cli2 0.22.0`，增加 `pnpm lint:md`，生成全仓库唯一的 `pnpm-lock.yaml`。该版本是经 npm 包元数据核对后仍支持项目 Node.js 20 基线的最高已检查版本；`0.23.2` 要求 Node.js 22，不适合作为当前项目依赖。
9. 更新根 `AGENTS.md`，要求 AI 修改 Markdown 后统一运行 `pnpm lint:md`；Markdown CI 门禁继续暂缓。
10. 将 pnpm 本地缓存目录 `.pnpm-store/` 加入 `.gitignore`，避免依赖缓存进入版本控制。
11. 在根 README、本地开发手册和 pnpm 命令速查中加入 `pnpm lint:md`，让开发者和 AI 都能从长期入口发现统一检查命令。
12. 验证结果：项目级 `pnpm lint:md` 使用 `markdownlint-cli2 0.22.0` 和 `markdownlint 0.40.0` 扫描 34 份 Markdown，结果为 0 个错误；VS Code 插件对应的 `markdownlint-cli2 0.23.2` 和 `markdownlint 0.41.1` 交叉扫描同样为 0 个问题。
13. 验证结果：`pnpm install --lockfile-only --frozen-lockfile`、`pnpm peers check`、文本卫生、JSON 配置、计划索引和 Git 差异检查均通过。
