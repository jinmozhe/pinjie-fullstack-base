# 母版发布链路可靠性回馈计划

## 1. 当前状态和结果

- 状态：已结束
- 结果：已完成；母版代码与文档回馈及适用轻量验证通过，真实云端发布未执行；Git 交付结果以对应 PR 和 Git 历史为准。
- 工作仓库：`pinjie-fullstack-base`。

## 2. 关联需求

无新增产品需求；属于既有 CNB、TCR、1Panel 发布链路的运维与可靠性修复。

## 3. 背景

Nav 发布暴露了远程缓存与正式发布共用失败路径、跨平台凭据归属不清、诊断信息不足和基础系统包漏洞等问题。母版仍含远程缓存参数，尚无对应的只读 CNB 诊断入口；已有独立发布和不可变镜像门禁继续保留。

## 4. 目标

同步适用代码与操作规范，使平台连接、故障分类、版本核对和成功判定可执行。保持母版仓库、镜像名、受保护环境与单镜像证据身份。

## 5. 非目标

不迁移 Nav 业务、凭据、发布 SHA、镜像 digest 或生产状态；不修改 CAM 实际授权、Secrets、Ruleset、生产环境和镜像保留数据。本次完成母版本地更新与适用验证，不自动提交、推送或触发母版镜像发布。

## 6. 现状分析

母版已有三端独立 Pipeline、人工全量入口、扫描及固定 digest 门禁。发布脚本仍读写 TCR Registry 缓存；部分校验失败缺少明确原因。Backend 采用与 Nav 修复前相同的固定基础镜像。Nav 只读诊断入口可提供适配基础，但母版须验证请求边界、响应结构与脱敏。

## 7. 方案设计

- 去掉 TCR Registry 缓存读写，保留 BuildKit 与 Trivy 其余缓存能力，明确导出失败处理，不添加整体忽略错误。
- 改进候选 metadata、digest、attestation 和 OCI 来源失败提示。
- 新增仅手动触发的只读诊断工作流，复用母版 `cnb-source-handoff` Environment，固定仓库与默认分支，限定 GET、拒绝重定向并限制查询量和时间；输出状态与脱敏错误摘要，查询完成不代表发布成功。
- 迁入 Backend 系统包升级步骤，保留固定基础镜像和既有包版本；记录构建时仓库包变化与真实扫描验证边界。
- 更新既有六份运维手册及必要索引，补齐凭据矩阵、可选本机核验、命名空间复用边界、事件白名单、独立发布与逐阶段验收。
- 根规则、第 17 节与 SECURITY：精确修改、保护未知内容、不输出凭据，运行已配置轻量门禁。ADR 0008：不覆盖 SHA 标签、不跳过扫描、不改变人工部署边界。

## 11. 风险与回滚

无远程缓存可能增加构建耗时；系统包升级会让未来构建读取新的可用包，生产仍固定最终 digest。诊断 Token 可能缺少构建读取权限，返回错误时不扩大权限或尝试写请求。回滚通过审阅差异逐项撤销本任务改动；运行中容器和现有镜像不受本地修改影响。母版真实云端发布须后续在对应授权下验证，不能用 Nav 结果代替。

## 12. 验证清单

- 诊断工作流语法、固定仓库/默认分支、只读请求、响应拒绝、凭据过滤与离线回归。
- 发布脚本回归、扫描与证据门禁、无 Registry 缓存参数检查。
- `pnpm lint:md`、`pnpm check:text`、`pnpm check:documents`、`pnpm check:workspace`、`pnpm check:boundaries`、`pnpm check:production-config`。
- 不运行本地安全扫描、pytest、Vitest、应用 production build、数据库迁移或生产部署。

## 15. 实施结果

- 已停用母版发布脚本的 TCR Registry 缓存读写；保留候选镜像、SBOM、provenance、扫描门禁和正式 SHA 标签不可覆盖约束。候选 metadata、digest、Registry 查询、attestation 与 OCI 标签校验失败有明确原因；digest 提取会读完输出，避免 pipefail 下提前关闭管道造成误报。
- 新增仅手动触发的母版只读诊断工作流及独立脚本，限定默认分支与固定母版仓库，复用原受保护环境 Token。按 CNB 官方 OpenAPI 的明确响应结构解析，不保留 Nav 的多形状猜测；200 次请求、20 页、总计 240 秒及单次 30 秒上限，GET 和拒绝重定向。错误日志仅输出固定分类，保留状态，不输出原始阶段日志或响应体。
- Backend runtime 增加系统包升级，母版已有应用源码、依赖锁文件、契约和迁移保持不变。构建缓存停用可能增加耗时；系统包仓库变化可能改变重建内容，仍须以正式候选扫描和最终 digest 为发布依据。
- 已统一六份运维手册的平台连接矩阵、Secret 实际归属、可选本机核验、命名空间复用边界、仓库/分支/事件白名单、独立发布与逐阶段成功判定；同步文档索引及 Changelog。未修改真实 CAM 策略、凭据、云端配置和母版仓库身份。
- 新增 `pnpm check:cnb-release`，复用现有发布、证据、扫描夹具并增加诊断回归，接入 `check:guards` 和 Governance CI。离线验证覆盖构建失败、缺少 metadata、Registry 查询失败、digest 不符、attestation/来源校验失败、不可变标签冲突、无远程缓存参数、401/403/302/500、错误响应、错仓库/SHA、空阶段、重复记录、分页与请求上限、日志秘密不进入报告。
- `pnpm check:cnb-release`、`pnpm lint:md`、`pnpm check:documents`、`pnpm check:text`、`pnpm check:workspace`、`pnpm check:boundaries`、`pnpm check:production-config` 和技能文本卫生检查通过。Markdown 初次发现计划末尾空行，修正后 177 份文档零告警。代码复读后补充边界的回归再次通过。
- 已直接读取 CNB 官方 OpenAPI 的构建历史、状态、Stage 接口和权限定义，以及 Docker 官方 GitHub Registry 缓存说明。工作流 YAML 由离线回归解析；Node 语法及 Git 差异检查通过。离线夹具创建的临时目录已自行清理，本次未启动项目服务或浏览器。

- Git 交付前复验 `pnpm check:governance`、Admin/Web 各自 typecheck 与 lint、Backend Ruff、格式、Mypy、导入边界、源码编译、应用导入及 OpenAPI 导出比对，全部通过；API Client 重新生成无漂移。未执行应用重型测试、本地安全扫描、真实镜像构建或部署。

- PR 线上 Semgrep 首次发现诊断摘要使用手工 HTML 转义，命中 `detect-replaceall-sanitization`。改为 GFM 缩进代码块保留完整 JSON 报告，并补充 HTML、反引号、换行和实体字符输入的离线回归；不增加扫描豁免或变更安全门禁。
