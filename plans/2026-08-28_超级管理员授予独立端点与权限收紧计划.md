# 超级管理员授予独立端点与权限收紧计划

## 当前状态和结果

- 状态：已结束
- 结果：已完成独立身份端点、系统权限隔离和超级管理员目标级保护；普通管理员无法编辑、停用、批量变更、分配角色、重置密码或查看及撤销超级管理员会话，Backend、Admin 和仓库轻量门禁通过。

## 关联需求

- `BASE-BE-005`：提供管理员身份、角色、权限和受保护管理接口。
- `BASE-BE-010`：Admin 管理端点声明准确资源权限并由服务端最终授权。
- `BASE-ADMIN-002`：受保护页面和操作不能只依赖界面隐藏。
- `BASE-ADMIN-004`：管理操作覆盖权限、成功和失败状态。
- `BASE-ADMIN-006`：Admin 通过共享 API Client 消费后端契约。

## 背景

当前 `admins:update` 同时用于管理员资料、状态和超级管理员身份变更。普通角色获得该权限后，可以通过管理员列表或直接请求把其他管理员设为超级管理员，权限粒度与高风险身份授予边界不匹配。用户确认保留普通资料更新能力，并为超级管理员授予建立独立端点和仅超级管理员可执行的双重服务端保护。

独立身份端点落地后继续发现目标级授权缺口：普通管理员只要拥有对应资源权限，仍可编辑超级管理员资料、分配角色、查看或撤销会话、重置密码，以及通过单条或批量接口停用超级管理员。资源权限只表达“可以执行哪类动作”，还必须结合目标管理员身份限制“可以操作谁”。

## 目标

- `admins:update` 继续负责管理员资料与状态，中文名称明确为“修改管理员资料与状态”。
- 新增 `admins:superuser:change`，中文名称为“设为超级管理员”。
- 新权限属于系统权限，不允许分配给普通角色。
- 新增独立超级管理员身份变更端点，要求 CSRF、准确权限、当前操作者为超级管理员、事务内状态校验和审计。
- 旧管理员资料更新端点不再接受 `is_superuser`，封闭历史绕过路径。
- 创建管理员时授予超级管理员身份同样要求操作者为超级管理员。
- Admin 仅向超级管理员展示可点击身份 Tag，普通管理员保持只读。
- 普通管理员不得对超级管理员执行资料编辑、角色分配、会话查看与撤销、密码重置、单条或批量状态变更。
- 超级管理员继续可以操作其他超级管理员，但本人保护和最后超级管理员保护保持有效。

## 非目标

- 不改变普通管理员之间现有的资料编辑、启停、角色分配、密码重置和会话管理能力。
- 不修改数据库结构或自动执行目标环境权限同步。
- 不通过前端隐藏替代后端授权。
- 不允许普通角色通过分配新权限获得超级管理员授予能力。

## 现状分析

- `PATCH /api/v1/admin/admins/{id}` 受 `admins:update` 保护，并接受 `is_superuser`。
- Admin 身份列只检查 `admins:update`，普通角色持有该权限即可触发身份变更。
- `AdminManagementService.update_admin` 已具备本人保护、最后超级管理员保护、凭据版本提升、会话撤销和审计，需要迁移到独立用例。
- 超级管理员通过当前身份上下文拥有完整源码权限目录，但服务端仍需事务内复核权威管理员状态。

## 方案设计

1. 权限目录新增不可分配给角色的 `admins:superuser:change`，同时明确 `admins:update` 中文语义。
2. 权限读取契约增加是否可分配给角色的字段，角色权限写服务拒绝系统权限码。
3. 新增超级管理员状态输入 Schema 和独立 Router 端点。
4. Dependency 同时检查准确权限和当前超级管理员身份，Service 在事务内再次读取操作者权威状态。
5. 从 `AdminUpdateIn` 移除 `is_superuser`，迁移既有身份变更逻辑至独立 Service 方法。
6. 创建管理员时仅在授予超级管理员身份时执行相同权威状态校验。
7. Admin API 封装改用新端点；身份列和创建表单按当前超级管理员身份控制。
8. 角色权限 Tree 显示系统权限但禁用选择，并在批量选择、保存和后端写入三处过滤。
9. 导出 OpenAPI、生成 API Client，再更新测试源码和文档。
10. 为所有管理员目标操作增加统一超级管理员目标保护，并同步 Admin 行级入口和批量选择限制。

## 风险与回滚

- 风险：旧资料更新端点仍可提交 `is_superuser`。
- 控制：从严格输入 Schema 移除字段，额外字段直接返回校验错误，并由契约与测试固定。
- 风险：普通角色获得新权限后绕过 UI 调用端点。
- 控制：权限标记为不可分配，角色写服务拒绝，并由 Dependency 和 Service 双重校验操作者真实超级管理员状态。
- 风险：创建管理员入口绕过独立端点保护。
- 控制：创建用例在 `is_superuser=true` 时执行同一事务内权威状态校验。
- 风险：契约和 Admin 消费漂移。
- 控制：固定执行 OpenAPI 导出、API Client 生成和 Admin typecheck。
- 风险：只在 Admin 隐藏操作，普通管理员仍可直接调用 Backend 或通过批量接口绕过。
- 控制：Service 对每个单条和批量目标读取数据库权威身份；目标包含超级管理员时要求操作者也是启用的超级管理员，Admin 只作为体验层同步禁用入口。
- 回滚：恢复旧 Schema 和 Admin 调用会重新引入已确认的提权风险，因此只允许前向修复，不把不安全旧行为作为生产回滚方案。
