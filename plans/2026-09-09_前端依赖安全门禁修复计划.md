## 实施顺序与文件

1. 登记本计划、`plans/INDEX.md` 与 `PROJECT_INDEX.md` 活动入口。
2. 在 `apps/web/package.json` 同步 Next.js 与配套 ESLint 插件，在 `pnpm-workspace.yaml` 精确修订受影响版本约束。
3. 由 pnpm 更新根 `pnpm-lock.yaml`，核对解析差异并执行 frozen-lockfile 安装，禁止手改锁文件或无关升级。
4. 运行受影响两端轻量检查、依赖策略及治理检查，更新 Changelog 与计划实际结果。
5. 同一 PR 追加提交，复验线上 Security 与必需门禁，rebase 合并后同步 main 并清理本次交付资源。

## 风险与回滚

- 补丁仍可能改变图像处理或构建工具行为，静态检查不能证明完整运行时兼容；未授权的 build、Vitest、pytest、Playwright 和数据库验证明确记录为未执行。
- 原依赖版本含已知 High/Critical 漏洞，不得以回退版本或降低门禁恢复合并；失败时保留分支并继续定位，同根因三次修复失败后停止本轮。
- 已提交文件通过 Git 历史和本次恢复记录保全。必要时以独立回滚 PR 撤销配置差异并保留安全阻断，禁止直接部署含漏洞的回退版本。
- 当前生产镜像未变化，源码修复不能表述为生产已修复；后续发布与部署仍需明确授权。
- override 负责人为仓库维护者，2026-09-23 复核。上游依赖范围已排除漏洞版本且锁文件解析安全时，删除本次 sharp 与 SVGO 精确 override；js-yaml 沿用已有治理条目，在原兼容范围安全后统一复核删除。删除前检查解析版本并通过两端静态检查及线上 Security。
