# Admin 技术栈文档一致性审计计划

## 当前状态和结果

- 状态：已结束
- 结果：已完成全仓库当前性文档、规则、索引、操作手册、CI、Docker、E2E 和历史方案的 Admin 技术栈一致性核对与修正；历史计划和原始方案保留原始事实并补充当前实现入口。

## 关联需求

- 无。本计划同步已确认的 Admin 技术栈事实，不新增产品能力。

## 背景

Admin 已从原有 Vite、Ant Design 5 叙述迁移到官方 Ant Design Pro v6、Umi Max、React、TypeScript、Ant Design 6、ProComponents 和 TanStack Query。仓库中仍可能存在旧技术栈、旧入口、旧命令和旧验证结论。

## 目标

1. 以 Admin 实际 `package.json`、Umi 配置和现行规则为事实基线。
2. 全量扫描 `README.md`、`docs/`、`plans/`、`AGENTS.md`、CI、Docker 和运维说明。
3. 修正当前性文档、索引和入口中的旧技术栈描述，保留历史计划的真实实施背景。
4. 运行 Markdown、文本、工作区和边界门禁，记录不能执行的验证项。

## 非目标

- 不修改 Admin 源码、依赖或运行配置。
- 不删除、移动、重命名或替换既有计划文档。
- 不把历史 ADR 或已结束计划改写成虚假的当时事实。

## 现状分析

- 当前 Admin 依赖为 `@umijs/max`、Ant Design 6、ProComponents、React 19 和 TanStack Query。
- 当前入口为 `apps/admin/src/app.tsx`，开发服务由 `scripts/run-umi.mjs` 固定 `PORT=3001`。
- 根 `README.md`、ADR 0001/0002/0003、环境变量手册和项目结构说明包含旧技术栈当前性表述，已完成修正；历史迁移计划、ADR 0011 的背景和原始规划方案中的旧技术栈均保留为历史记录。

## 方案设计

- 建立“实现事实、当前规则、历史记录”三类文档边界。
- 当前规则和操作文档统一写 Umi Max、Ant Design 6、ProComponents、React 19、TypeScript、TanStack Query、`app.tsx` 和 `pnpm --filter @pinjie/admin ...`。
- ADR 只在描述当前架构或长期决策的段落更新；原始方案与已结束计划保留历史语境，并补充迁移结果入口。
- `docs/README.md`、`PROJECT_INDEX.md`、`CHANGELOG.md` 只维护索引和已交付事实，不复制实现细节。

## 实施顺序

1. 建立计划并锁定实现事实基线。
2. 扫描并分类全部旧技术栈引用。
3. 更新当前文档和索引，保留历史记录语义。
4. 复读差异并运行文档、治理和边界检查。
5. 回写计划、索引和 Changelog。
