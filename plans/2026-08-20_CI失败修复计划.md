# CI 失败修复计划

## 当前状态和结果

- 状态：已完成
- 结果：Backend、Web、Admin、Markdown、依赖审计和治理检查已完成本机复验；Linux CI 的 Umi/Vite 兼容性仍需线上工作流复核。

## 关联需求

- 无。本计划修复现有 CI 质量与安全门禁，不新增产品能力。

## 背景

提交 `5b87ad5` 的线上检查暴露了 Backend Ruff 格式、Web 测试 matcher 类型和 Node 依赖漏洞问题；前一提交还暴露了 Admin 入口文件名大小写导致的 Linux 工作区状态失败。

## 目标

1. 使 Backend Ruff 格式门禁通过。
2. 使 Web TypeScript 能识别 Testing Library matcher。
3. 升级可安全升级的 Node 依赖并降低高危漏洞。
4. 在不跳过门禁的前提下通过本地等价验证。

## 非目标

- 不改变业务行为、公开 API、数据库结构或生产部署流程。
- 不关闭或放宽安全扫描门禁。

## 现状分析

- `uv run ruff format --check .` 报告两个 Backend 文件需要格式化。
- Web `tsc --noEmit` 报告 `jest-dom` matcher 类型缺失。
- `pnpm audit --audit-level high` 报告 50 个漏洞，其中 1 个 critical、16 个 high。
- 阶段二已将 Admin 入口从 `App.tsx` 修正为 Linux 兼容的 `app.tsx`。

## 方案设计

- 使用 Ruff formatter 规范 Backend 文件，并复跑 Backend 静态检查。
- 为 Web TypeScript 显式加载 Vitest 与 Testing Library matcher 类型，保留现有运行时 setup。
- 优先使用锁文件允许的安全升级路径，复跑安装、审计和前端质量检查；无法由直接升级消除的传递依赖记录剩余风险。

## 实施顺序

1. 建立计划并确认工作区状态。
2. 修复 Backend 格式和 Web 类型配置。
3. 升级 Node 依赖、审查锁文件和漏洞结果。
4. 运行分层质量检查与契约漂移检查。
5. 回写计划、索引和 Changelog。

- `apps/backend/app/core/payload_sanitizer.py`

## 风险与回滚

- 依赖升级可能引入 API 或构建行为变化；通过锁文件 diff、全量前端质量检查和 Git 回滚恢复。
- 仍可能存在暂无修复版本的传递依赖；不得伪装为全部漏洞已消除，应在计划剩余问题中记录。

## 实施结果

- Ruff formatter 已规范两个 Backend 文件，Web `tsconfig.json` 已显式加载 `vitest/globals` 与 `@testing-library/jest-dom` 类型。
- Web 测试 setup 已显式执行 `expect.extend(matchers)`，修复 Vitest 运行时 `toBeInTheDocument` 等 matcher 未注册问题。
- `pnpm-workspace.yaml` 增加 `immer`、`node-fetch`、`axios`、`image-size` 和 `vite` 的精确安全 overrides，锁文件已重新生成并通过 supply-chain policy 校验。
- 本地 `pnpm audit --audit-level high` 已无 high/critical 漏洞。
- Docker Desktop Redis 已启动并返回 `PONG`；本机 PostgreSQL 18 服务运行且 `pg_isready` 报告 5432 accepting connections；测试数据库已升级到 Alembic head。
- 工作区状态、模块边界、文本卫生、Markdown 和治理 guard 均通过。

## 剩余问题

- Umi 4.7.5 的传递 Vite 已通过 `pnpm` override 解析到 6.4.3；Windows Admin production build 已通过，Linux CI 仍需线上工作流复验构建和 E2E 兼容性。
- pnpm 链接问题由受限终端无法访问用户级缓存/链接目录导致；在有权限终端执行 `pnpm install --frozen-lockfile --prefer-offline` 已成功链接 1727 个依赖。
- Admin 测试仍会输出 CSS parser warning 并耗时约 250 秒，但 17 项全部通过；该警告不影响当前门禁结果。
