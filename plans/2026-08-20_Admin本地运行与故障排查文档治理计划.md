# Admin 本地运行与故障排查文档治理计划

## 1. 当前状态和结果

- 状态：已结束
- 结果：已完成

## 2. 关联需求

- 无。本计划整理已完成 Admin 迁移中的运行、测试和系统故障事实，不新增产品能力。

## 3. 背景

Admin 迁移期间发现 Umi 启动参数、运行时环境变量、initialState、生成目录和 jsdom 导航等问题；本机同时发生 Windows 蓝屏重启。需要把可复用的排障步骤与长期规则分层保存，避免后续把局部兜底验证误写成完整跨栈通过。

## 4. 目标

1. 建立 Admin 本地运行、测试、浏览器和跨栈验证的排障手册。
2. 将稳定且可机械执行的规则同步到根和 Admin 级 `AGENTS.md`。
3. 在文档索引、项目索引和 Changelog 中留下可追溯入口。

## 5. 非目标

- 不修改 Admin 业务代码、后端接口或部署配置。
- 不把本次蓝屏的具体驱动版本固化为项目运行时要求。
- 不声称 Docker、Backend、PostgreSQL 或 Redis 未启动时已完成真实跨栈 E2E。

## 6. 实施结果

- 新增 `docs/operations/admin-local-development-and-validation-troubleshooting.md`，记录 Umi 端口、环境变量、生成目录、测试、浏览器、跨栈前置条件、迁移运行错误和本次蓝屏证据。
- 根 `AGENTS.md` 新增长期本地运行与验证边界；`apps/admin/AGENTS.md` 新增 Umi 专项启动和测试规则。
- 已同步 `docs/README.md`、`PROJECT_INDEX.md` 和 `CHANGELOG.md`。

## 7. 验证

- 运行 `pnpm lint:md`、`pnpm check:text`、`pnpm check:workspace` 和 `pnpm check:boundaries`。
- 复读所有修改文件，检查 UTF-8 无 BOM、链接、命令和状态描述。

## 8. 剩余问题

- 本计划不改变 Admin 迁移计划中已记录的环境限制。完整跨栈 E2E 仍需 Docker Desktop、Backend、PostgreSQL 和 Redis 同时可用。
