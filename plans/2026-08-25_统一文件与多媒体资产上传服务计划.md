## 3. 背景

当前母版已具备完整的用户/管理员双域认证、会话隔离与 RBAC 权限体系。但在实际业务派生（如 CMS 文章配图、商品图册、用户与管理员头像更换、系统导入导出文档等）中，需要一套标准、安全、统一的文件与多媒体资产管理服务。当前管理员 `avatar` 仅保存外部 URL 字符串，缺乏本地/云端文件上传落盘、元数据记录与统一管理能力。

---

## 4. 目标

1. **后端存储驱动解耦**：提供通用的存储适配器接口（`StorageProvider`），默认支持本地磁盘存储（`local`），并支持平滑扩展至云对象存储（`s3`、`oss`、`cos`、`minio`）。
2. **场景与单层日期目录规范**：文件落盘路径按业务场景与紧凑年月日单层目录组织，格式为 `uploads/{scene}/{YYYYMMDD}/{file_hash[:16]}_{filename}.{ext}`，兼顾分桶防 Inode 性能衰退与目录紧凑性。
3. **双域上传者元数据持久化**：建立统一的 `assets`（资产多媒体表），通过 `uploader_type` + `uploader_id` 完美兼容 B 端管理员、C 端用户与 System 异步任务上传，记录文件大小、MIME 类型、SHA-256 哈希，支持秒传去重与审计溯源。
4. **.env 驱动与分层安全校验**：在 `.env` 中定义全局存储路径、体积配额与全局扩展名白名单；在后端 Scene 策略中定义场景级 MIME 与 Magic Number 二进制文件头探测，全面防御木马与恶意脚本注入。
5. **前端标准化组件**：在 Admin 和 Web 端封装开箱即用的 `<ImageUploader />` 与 `<AvatarUploader />` 组件，无缝对接统一接口。

---

## 5. 非目标

1. 本阶段不引入重型视频转码工作流（如 FFmpeg 分片转码由派生项目按需引入）。
2. 本阶段不强制绑定特定商业云厂商 SDK，优先保障零依赖本地存储驱动与标准 S3/MinIO 兼容协议。

---

## 6. 现状分析

1. **后端现状**：FastAPI 后端目前未提供 `multipart/form-data` 处理模块，缺少静态资源挂载配置与 `assets` 数据表。
2. **前端现状**：个人设置页目前通过手动输入头像 URL 方式联动，缺乏点击上传本地图片并自动回填 URL 的交互组件。

## 7. 方案设计与关键设计决策

### 7.1 存储目录与文件命名规范

文件落盘路径采用紧凑单层日期目录结构：

```text
uploads/
  ├── avatar/
  │   └── 20260825/
  │       └── a1b2c3d4e5f60708_avatar.webp
  ├── article/
  │   └── 20260825/
  │       └── 9f8e7d6c5b4a3210_cover.jpg
  ├── product/
  │   └── 20260825/
  │       └── 3c4d5e6f7a8b9c0d_sku_main.png
  └── document/
      └── 20260825/
          └── 1234567890abcdef_contract.pdf
```

### 7.2 `{scene}` 场景定义与策略映射

`scene`（业务场景）是受控枚举，前端上传时传入具体场景，后端根据场景动态应用对应的安全策略与校验规则：

```python
class UploadScene(str, Enum):
    AVATAR = "avatar"        # 用户/管理员头像 (限 jpg/png/webp, 单文件 <= 2MB)
    ARTICLE = "article"      # CMS 文章/博客配图 (限 jpg/png/webp/gif, 单文件 <= 5MB)
    PRODUCT = "product"      # 电商商品图/详情图 (限 jpg/png/webp, 单文件 <= 10MB)
    DOCUMENT = "document"    # 业务文档/合同/PDF/表格 (限 pdf/doc/docx/xls/xlsx, <= 30MB)
    ATTACHMENT = "attachment"# 通用附件 (受全局白名单控制)
    TEMP = "temp"            # 临时解析导入文件 (系统可定期清理)
```

### 7.3 数据库模型设计 (`assets` 表)

采用 `uploader_type` + `uploader_id` 复合主体设计，完美适配全栈母版的 Dual-Principal（用户与管理员双域隔离）架构：

| 字段名 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `UUID` | UUID v7 唯一主键 |
| `uploader_type` | `VARCHAR(20)` | 上传者类型：`admin` (管理员) / `user` (普通用户) / `system` (系统任务) |
| `uploader_id` | `UUID` | 上传者主键 ID（对应 `admins.id` 或 `users.id`，system 时可置空） |
| `storage_driver` | `VARCHAR(20)` | 存储驱动：`local` / `s3` / `oss` / `cos` / `minio` |
| `file_key` | `VARCHAR(500)` | 存储相对路径或对象 Key (如 `avatar/20260825/xxx.webp`) |
| `original_name` | `VARCHAR(255)` | 用户上传时的原始文件名 |
| `mime_type` | `VARCHAR(100)` | 文件真实 MIME 类型 |
| `file_size` | `BIGINT` | 文件实际字节大小 |
| `file_hash` | `VARCHAR(64)` | SHA-256 哈希值 (用于秒传去重与数据完整性校验) |
| `url` | `VARCHAR(1000)` | 可公开访问的完整或相对 URL |
| `scene` | `VARCHAR(50)` | 业务场景标识 (`avatar`, `article` 等) |
| `created_at` | `TIMESTAMPTZ` | 创建时间 |
| `updated_at` | `TIMESTAMPTZ` | 更新时间 |

### 7.4 `.env` 环境变量与安全机制

在后端的 `.env.example` 与 `Settings` 中提供全局控制开关：

```env
# ==============================================================================
# 文件与多媒体存储配置
# ==============================================================================
UPLOAD_STORAGE_DRIVER=local
UPLOAD_LOCAL_ROOT=uploads
UPLOAD_BASE_URL=/static/uploads
UPLOAD_MAX_FILE_SIZE_MB=50
UPLOAD_ALLOWED_EXTENSIONS=jpg,jpeg,png,webp,gif,svg,pdf,doc,docx,xls,xlsx,zip
```

#### 安全防御管道

1. **扩展名与 MIME 双重白名单**：拒绝 `.exe`、`.sh`、`.py`、`.php` 等一切可执行文件。
2. **Magic Number 文件头二进制探测**：使用 `filetype` 或 Python 内置二进制头探测真实格式，防御伪装后缀的木马文件。
3. **静态目录执行权限隔离**：静态资源目录在 Nginx / FastAPI 中配置为纯静态文件响应，禁止任何执行解析。
4. **文件名脱敏混淆**：落盘时一律采用 `hash[:16] + 随机 uuid` 重新命名，防止目录遍历攻击（Path Traversal）。

### 7.5 API 接口契约设计

- `POST /api/v1/assets/upload`：通用上传接口（接收 `file: UploadFile`, `scene: UploadScene`）。
- `GET /api/v1/assets`：管理员资产库分页查询接口。
- `DELETE /api/v1/assets/{id}`：资产删除接口。

## 11. 风险与回滚

1. **磁盘空间监控**：本地存储需设置全局单文件最大体积配额。
2. **安全风险防范**：静态资源目录严格隔离执行权限，上传文件名强制脱敏混淆。
3. **回滚机制**：若出现异常，可通过 Alembic 降级迁移，保留原有纯 URL 模式。
