## 背景

Admin 已完成 Ant Design Pro v6/Umi Max 迁移，但后续讨论发现既有规则存在两个事实漂移：`apps/admin/AGENTS.md` 仍把 `src/pages/` 写为路由页面目录，而当前配置式路由实际指向 `src/features/**Page.tsx`；ADR 0011 把 Umi Request 列为采用能力，而当前 Browser Cookie、CSRF、单飞 Refresh、错误解包和二次确认头由项目自有 `src/lib/api/http.ts` 统一承担。

同时，原有文档尚未完整区分 Umi 管理的核心运行边界、项目管理的安全和契约边界、可以评审引入的外围依赖，以及只应进入派生仓库的业务依赖。若继续使用“业务依赖自由升级”或“必须使用所有 ProComponents 高阶组件”等绝对表述，会与母版供应链规则和当前实现冲突。

## 目标

1. 在 Admin 宪法中固化 Umi 公共入口、框架核心依赖、项目安全 HTTP 管道、依赖准入和 ProComponents 使用红线。
2. 新增 Admin 工程实施标准，详细说明路由、生命周期、Access、数据请求、UI 组件选择、依赖升级和验证范式。
3. 修正 `src/pages` 与 `src/features` 的目录事实，以及 ADR 0011 的 Umi Request 表述。
4. 保持当前源码、公开契约、业务行为、依赖解析和生产配置不变。

## 非目标

- 不迁移现有 Feature、页面、请求代码或路由路径。
- 不强制把现有页面改写为 `ProTable`、`ModalForm` 或 `DrawerForm`。
- 不升级 Umi、React Router、Ant Design、ProComponents 或其他依赖。
- 不新增业务第三方库，不修改 Backend、Web、API Client、数据库或部署流程。
- 不提交或推送；Git 动作继续单独授权。

## 现状分析

### 已有正确边界

- Umi Max 管理配置式路由、ProLayout、运行时 `app.tsx` 和客户端 Access。
- Browser Cookie、CSRF、单飞 Refresh、服务端 RBAC、二次确认和审计链优先于官方 Demo。
- Admin 使用 `@pinjie/api-client` 生成类型，服务端数据由 TanStack Query 管理。
- Ant Design 和 ProComponents 是首选管理端组件体系，但现有规则没有要求每个页面必须使用高阶 ProComponents。

### 待修正边界

- `src/pages/` 规则与当前 `config/routes.ts` 指向 `src/features/**Page.tsx` 的实现不一致。
- ADR 0011 的 Umi Request 表述与当前唯一安全 HTTP 管道不一致。
- 尚未明确禁止直接声明或强制升级 Umi 管理的路由、构建器和运行时内部依赖到不兼容主版本。
- 尚未明确母版中的业务外围库并非自由准入，具体业务依赖应由真实需求或派生仓库承接。

## 方案设计

### 1. 宪法级红线

更新 `apps/admin/AGENTS.md`：

- Umi 核心能力只通过 `@umijs/max`、配置和插件公开入口使用。
- 禁止直接接管 Umi 的路由、构建和运行时内部依赖，禁止强制升级到 Umi 未支持的主版本。
- 安全 override 只能在专项计划、受影响范围、依赖证据和完整回归齐备时使用；无兼容修复版本时遵守限时风险接受。
- 项目 HTTP 管道是 Admin 唯一传输入口；Umi Request、另一套生成 SDK 或页面原始 `fetch` 不得形成第二套请求事实来源。
- Ant Design 和 ProComponents 优先但不强制，组件选择按页面复杂度、性能和交互契约决定。
- 具体业务依赖默认进入派生仓库，母版只接收业务中立且有明确复用价值的能力。

### 2. Admin 工程标准

新增 `docs/architecture/admin-engineering-standard.md`，保存详细目录职责、路由与生命周期、Access 与服务端授权、请求和状态、组件选择矩阵、依赖治理、页面状态和验证要求。Admin 宪法只保留长期强制约束和入口链接。

### 3. ADR 与导航同步

- 在 ADR 0011 中澄清：Umi 管理路由、布局、生命周期和插件契约；项目自有 HTTP 管道是有意保留的安全适配层，Umi Request 不作为并行客户端。
- 更新 Admin README、`docs/README.md`、项目结构清单、全项目索引和 Changelog。

## 风险与回滚

- 规则过度绝对化可能阻止合理技术选择，因此宪法只定义禁止绕过、单一事实来源和验证要求，具体组件选择进入工程标准。
- 文档若继续复制完整规则会形成多份来源，因此 ADR 保存取舍、工程标准保存机制、Admin AGENTS 保存红线，README 只保留入口。
- 本任务不修改源码和依赖；如文档与实现复核不一致，回退本次文档差异并保持当前运行实现不变。
